# 작문 시스템 명세

## 1. 네 층의 분리

Lore Studio의 작문 품질은 다음 네 층을 분리하는 데서 시작한다.

```text
Concept Pages     무엇에 대해 쓸 것인가
Direction Cards   이 프로젝트 글에서 무엇을 강조·금지할 것인가
Writing Recipe    정보를 어떤 순서로 공개할 것인가
Output Profile    최종 매체에 맞게 어떻게 표현할 것인가
```

하나의 자연어 프롬프트로 이 네 역할을 뭉치면 재사용과 수정이 어려워지고, 어떤 선택이 결과에 영향을 주었는지 알 수 없게 된다.

## 2. 공유 전개 방식은 목차나 결과물 형식이 아니다

나쁜 레시피:

```text
1. 기원
2. 외형
3. 능력
4. 부작용
5. 결말
```

이 구조는 특정 소재에만 적용된다.

좋은 레시피:

```text
넓은 맥락에서 독자를 위치시킨다.
대상으로 시야를 좁힌다.
확정 사실을 배치한다.
통념으로 설명되지 않는 예외를 추가한다.
추상 설명 뒤에 구체적 사례를 둔다.
사실의 세계관적 의미와 파급을 확대한다.
충분히 설명하되 근본 원인은 완전히 닫지 않는다.
```

이는 유물, 행성, 종족, 전쟁, 기술, 종교, 기관 등 다양한 소재에 재사용할 수 있다.

## 3. 수사적 이동(Rhetorical Move)

레시피는 문단이 수행하는 역할을 Move로 정의한다.

| Move | 기능 |
|---|---|
| `ORIENT` | 시대·장소·사회·우주적 맥락에 독자를 위치시킨다. |
| `NARROW` | 넓은 배경에서 이번 대상으로 초점을 좁힌다. |
| `ANCHOR` | 확정된 핵심 사실이나 관찰을 제시한다. |
| `COMPLICATE` | 기존 설명으로 풀리지 않는 예외·모순·대가를 추가한다. |
| `COMPARE` | 알려진 것과 비교해 낯선 대상을 이해시킨다. |
| `EXEMPLIFY` | 추상 규칙을 사건·사물·개인의 결과로 구체화한다. |
| `ESCALATE` | 위험·규모·시간·사회적 파급을 확대한다. |
| `INTERPRET` | 사실이 세계관에서 갖는 의미를 해석한다. |
| `WITHHOLD` | 근거 없는 해답을 피하고 의도적 미지를 보존한다. |
| `TURN` | 앞서 형성한 기대나 의미를 뒤집는다. |
| `STING` | 짧고 강한 문장으로 절이나 글을 닫는다. |

레시피는 모든 Move를 고정 순서로 강제하지 않는다. 필수 Move, 선택 Move, 조건부 삽입 규칙, 금지되는 반복을 정의한다.

## 4. 기본 공유 전개 방식

| 전개 방식 | 정보 공개 순서 |
|---|---|
| 큰 맥락에서 핵심으로 | 큰 맥락 → 핵심 대상 → 사례·예외 → 의미 |
| 현재 흔적에서 과거로 | 현재의 흔적 → 변화 이전 → 결정적 사건 → 달라진 의미 |
| 목표에서 결과로 | 목표 → 방해 → 선택 → 결과 |
| 증거에서 판단으로 | 관찰 사실 → 증거 비교 → 모순·빈틈 → 판단 |
| 원인에서 파급으로 | 시작 원인 → 작동 과정 → 개인의 결과 → 사회의 파급 |
| 통념에서 재해석으로 | 익숙한 통념 → 반대 사례 → 숨은 조건 → 재해석 |

이 여섯 방식은 `project_id=NULL`인 공유 프리셋이다. 프로젝트의 인물·장소·사건을 포함하지 않으며, 세계관 설명 글·소설 장면·영상 내레이션·세계 내부 문서 같은 결과물 형식과도 독립적이다.

## 5. 프로젝트 집필 지침(DirectionCard)의 역할

집필 지침은 프로젝트에 속하며, 프로젝트와 무관한 공유 전개 방식과 다르다.

- “큰 맥락 → 핵심 대상 → 사례·예외 → 의미 순서로 써라”는 공유 전개 방식이다.
- “해결책의 실제 효능과 사회적 대가를 함께 보여 줘라”는 프로젝트 집필 지침이다.
- “기억을 먹는 항로와 수도회를 사용하라”는 컨셉 선택이다.
- “영상 내레이션으로 6분 분량”은 출력 프로필과 분량 설정이다.

카드는 다음 구조를 가질 수 있다.

```json
{
  "must_include": ["초기 효능은 실제로 유용하다"],
  "avoid": ["효능이 처음부터 거짓이었다는 반전"],
  "sequence": ["도입", "성공", "의존", "대가", "정착"],
  "ending_preference": "완전한 해결보다 지속되는 구조"
}
```

사용자 원문은 항상 보존하고, 구조화 결과는 보조 해석으로 취급한다.

## 6. Output Profile

같은 소재와 레시피도 매체에 따라 다르게 실현한다.

### 설정 글

- 중간~긴 문장
- 높은 정보 밀도
- 문단 단위 논리 전개
- 근거는 내부 메타데이터 또는 각주

### 영상 내레이션

- 발화하기 쉬운 문장
- 한두 문장마다 시각 비트
- 괄호·긴 삽입절 최소화
- 생성 후 TTS 실측 길이로 조정

### 소설 장면

- 장면 내부 시간의 연속성
- 인물 시점과 감각
- 설명보다 행동·대화 비중 증가

## 7. 작문 감사

### Canon Auditor

- 출처 없는 고유 사실
- 다른 네임스페이스의 혼입
- 확정 사실과 추론 혼동
- 시대·관계 충돌
- 폐기 설정 사용

### Discourse Auditor

- 추상 설명만 연속됨
- 같은 결론 반복
- 규모 변화 없이 평면적으로 나열
- 사례가 설명을 증명하지 않음
- 모든 문단에 억지 반전
- 결말이 앞 내용을 단순 요약

### Style Auditor

- 상투어·접속사 반복
- 문장 길이 단조로움
- 추상명사 과다
- 선택한 서술자 위치 이탈
- 참고 표본 문구의 과도한 유사성

## 8. 참고 표본 분석

참고 글은 `DISCOURSE_REFERENCE`로 저장한다. 사실 검색에는 사용하지 않고 다음만 추출한다.

- 문단별 Move
- 스케일 변화: 우주→사회→대상→개인 등
- 확실성 변화: 확정→보고→논쟁→미지
- 정보 밀도
- 문장 길이 패턴
- 전환 방식
- 문단 종결 기능

분석 결과를 사용자가 검토한 뒤 집필 레시피와 Voice Profile로 승격한다.
