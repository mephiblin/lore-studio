# 작문 시스템 명세

## 1. 여섯 층의 분리

Lore Studio의 작문 품질은 다음 여섯 층을 분리하는 데서 시작한다.

```text
Concept Pages     무엇에 대해 쓸 것인가
Direction Cards   이 프로젝트 글에서 무엇을 강조·금지할 것인가
Writing Recipe    정보를 어떤 순서로 공개할 것인가
Voice Profile     어떤 문장 호흡과 표현 원칙으로 전달할 것인가
Output Profile    어떤 결과물 형태와 매체로 표현할 것인가
Sampling Profile  런타임에서 문장 후보의 안정성과 다양성을 어떻게 조절할 것인가
```

하나의 자연어 프롬프트로 이 여섯 역할을 뭉치면 재사용과 수정이 어려워지고, 어떤 선택이 결과에 영향을 주었는지 알 수 없게 된다. 분량은 이 여섯 층과 별개의 플레이북 생성 계약이다.

## 2. 전개 방식은 목차나 결과물 형태가 아니다

나쁜 레시피:

```text
1. 기원
2. 외형
3. 능력
4. 부작용
5. 결말
```

이 구조는 특정 소재에만 적용된다.

좋은 레시피:

```text
넓은 맥락에서 독자를 위치시킨다.
대상으로 시야를 좁힌다.
확정 사실을 배치한다.
통념으로 설명되지 않는 예외를 추가한다.
추상 설명 뒤에 구체적 사례를 둔다.
사실의 세계관적 의미와 파급을 확대한다.
충분히 설명하되 근본 원인은 완전히 닫지 않는다.
```

이는 유물, 행성, 종족, 전쟁, 기술, 종교, 기관 등 다양한 소재에 재사용할 수 있다.

## 3. 수사적 이동(Rhetorical Move)

레시피는 문단이 수행하는 역할을 Move로 정의한다.

| Move | 기능 |
|---|---|
| `ORIENT` | 독자가 글의 질문과 상황을 이해하도록 필요한 맥락을 연다. |
| `NARROW` | 넓은 주제에서 이번 대상이나 쟁점으로 초점을 좁힌다. |
| `ANCHOR` | 중심이 되는 근거, 관찰, 장면 또는 주장을 구체적으로 제시한다. |
| `COMPLICATE` | 첫 설명만으로 풀리지 않는 문제·예외·반론·대가를 검토한다. |
| `COMPARE` | 대상, 관점, 전후 상황을 비교해 차이와 기준을 드러낸다. |
| `EXEMPLIFY` | 추상적인 생각이나 규칙을 구체적인 사례 또는 장면으로 보여 준다. |
| `ESCALATE` | 갈등, 중요도, 영향 범위를 높여 다음 판단이나 선택으로 이끈다. |
| `INTERPRET` | 앞서 제시한 근거나 경험의 의미를 분석하고 해석한다. |
| `WITHHOLD` | 근거가 부족한 답을 단정하지 않고 질문이나 판단을 유보한다. |
| `TURN` | 새 근거·반론·깨달음으로 글의 관점이나 방향을 전환한다. |
| `STING` | 핵심 결론·이미지·질문으로 글의 의미와 여운을 남긴다. |

레시피의 `required_moves`는 카드에 보이는 순서이자 AI가 처음 만드는 글의 흐름에 적용하는 고정 순서이며, 완성 원고 점검도 같은 값을 기준으로 삼는다. 별도의 `카드 표시` 순서는 두지 않는다. 각 Move의 이름과 목적은 위 표의 전역 사전에서 자동 파생하고 사용자가 다시 작성하지 않는다. 방식마다 달라지는 구체적인 구성 의도는 `planner_rules`, 완성 후 확인 기준은 `audit_rules`에 둔다. 사용자가 글의 흐름 화면에서 명시적으로 바꾼 순서는 허용하되, 완성 원고 점검에서 필수 순서와 다른 부분을 경고한다.

## 4. 기본 공유 전개 방식

| 전개 방식 | 실제 필수 Move 순서 |
|---|---|
| 큰 맥락에서 핵심으로 | 맥락 열기 → 초점 좁히기 → 핵심 근거·장면 → 문제·예외 검토 → 의미·분석 |
| 현재 흔적에서 과거로 | 핵심 근거·장면 → 맥락 열기 → 문제·예외 검토 → 긴장·중요도 높이기 → 관점 전환 |
| 목표에서 결과로 | 핵심 근거·장면 → 문제·예외 검토 → 긴장·중요도 높이기 → 관점 전환 → 의미·분석 |
| 증거에서 판단으로 | 핵심 근거·장면 → 비교·대조 → 문제·예외 검토 → 의미·분석 |
| 원인에서 파급으로 | 맥락 열기 → 핵심 근거·장면 → 사례·장면 → 긴장·중요도 높이기 → 의미·분석 |
| 통념에서 재해석으로 | 맥락 열기 → 핵심 근거·장면 → 비교·대조 → 문제·예외 검토 → 관점 전환 |
| 경험에서 통찰로 | 핵심 근거·장면 → 의미·분석 → 문제·예외 검토 → 관점 전환 → 결론·여운 |
| 질문에서 결론으로 | 맥락 열기 → 핵심 근거·장면 → 비교·대조 → 문제·예외 검토 → 의미·분석 |
| 현장 징후에서 경고로 | 맥락 열기 → 핵심 근거·장면 → 사례·장면 → 답을 유보하기 → 긴장·중요도 높이기 → 결론·여운 |
| 발췌에서 종합 해설로 | 맥락 열기 → 핵심 근거·장면 → 사례·장면 → 의미·분석 → 비교·대조 |
| 공간 순례에서 귀결로 | 맥락 열기 → 핵심 근거·장면 → 긴장·중요도 높이기 → 관점 전환 → 결론·여운 |

이 열한 방식은 `project_id=NULL`인 공유 프리셋이다. `목표에서 결과로`는 소설 장면, `경험에서 통찰로`는 수필·에세이, `질문에서 결론으로`는 일반 분석 보고서, `현장 징후에서 경고로`는 제한된 화자의 구술, `발췌에서 종합 해설로`는 원자료 큐레이션, `공간 순례에서 귀결로`는 상징적 우화를 명시적으로 지원한다. 사용자는 같은 Move 체계를 사용해 프로젝트 전용 방식을 만들 수 있다. 두 종류 모두 프로젝트의 인물·장소·사건을 내용으로 포함하지 않으며 결과물 형태와도 독립적이다.

## 5. 프로젝트 집필 지침(DirectionCard)의 역할

집필 지침은 무엇을 강조하거나 금지할지 정하고, 전개 방식은 정보를 공개할 순서를 정한다. 둘 다 프로젝트 소유 항목을 가질 수 있지만 역할은 합치지 않는다.

- “큰 맥락 → 핵심 대상 → 사례·예외 → 의미 순서로 써라”는 전개 방식이다.
- “해결책의 실제 효능과 사회적 대가를 함께 보여 줘라”는 프로젝트 집필 지침이다.
- “기억을 먹는 항로와 수도회를 사용하라”는 세계관 자료 선택이다.
- “영상 내레이션으로 6분 분량”은 결과물 형태와 분량 설정이다.

카드는 다음 구조를 가질 수 있다.

```json
{
  "must_include": ["초기 효능은 실제로 유용하다"],
  "avoid": ["효능이 처음부터 거짓이었다는 반전"],
  "sequence": ["도입", "성공", "의존", "대가", "정착"],
  "ending_preference": "완전한 해결보다 지속되는 구조"
}
```

사용자 원문은 항상 보존하고, 구조화 결과는 보조 해석으로 취급한다.

## 6. 결과물 형태(Output Profile)

같은 소재와 레시피도 매체에 따라 다르게 실현한다.

### 설정 글

- 중간~긴 문장
- 높은 정보 밀도
- 문단 단위 논리 전개
- 근거는 내부 메타데이터 또는 각주

### 영상 내레이션

- 발화하기 쉬운 문장
- 한두 문장마다 시각 비트
- 괄호·긴 삽입절 최소화
- 생성 후 TTS 실측 길이로 조정

### 소설 장면

- 장면 내부 시간의 연속성
- 인물 시점과 감각
- 설명보다 행동·대화 비중 증가

### 수필·에세이

- 구체적인 경험·관찰을 추상적 성찰보다 먼저 배치
- 경험을 곧바로 보편적 교훈으로 확대하지 않음
- 달라진 시선과 열린 여운으로 마무리

### 분석 보고서

- 조사 질문과 판단 기준을 먼저 명시
- 사실·해석·결론·권고의 층위를 분리
- 근거의 한계보다 강한 결론을 내리지 않음

### 세계 내부 구술

- 화자·청자·말하는 장소와 화자의 욕망이 드러나는 한 목소리
- 주요 정보를 직접 목격·출처 있는 전언·화자의 추측으로 구분
- 화자가 알 수 없는 사실과 공개 유보 정보를 전지적으로 해설하지 않음
- 메모 항목이나 분석 요약 없이 경고·거래·행동으로 마무리된 원고만 출력
- 별도의 최대 토큰·고정 글자 수 없이 글 만들기의 기존 분량 계약을 사용

### 자료 큐레이션·해설

- 사용자 조건에 맞는 서로 다른 가치의 원자료를 선별
- 제공된 실제 문구만 짧게 직접 인용하고 간접화법은 의역으로 유지
- 원자료의 사건 순서와 의미를 보존한 상세 의역 뒤에 해설자의 판단을 분리
- 전체 끝에서 자료 사이의 변화·차이·공통 주제를 종합

### 상징적 우화 단편

- 외부 이야기꾼이 공간의 순서와 집단의 움직임을 내려다보듯 서술
- 반복 신호의 물리적 특성은 고정하고 그에 대한 집단의 반응만 변화
- 상징의 뜻을 직접 해설하거나 참고 작품의 고유 문구·소품을 복제하지 않음
- 이미 세운 공간 규칙의 붕괴와 짧은 물리적 이미지로 종결

## 7. 생성 성향(Sampling Profile)

Sampling Profile은 결과물 의미나 문체 규칙이 아니라 Writer 호출의 확률적 후보 범위를 정의한다.

| 생성 성향 | 기본 용도 | temperature / top-p / top-k |
|---|---|---|
| 정밀 | 분석·자료 해설·설정 정리 | 0.38 / 0.82 / 24 |
| 균형 | 세계관 설명·영상·세계 내부 문서 | 0.58 / 0.86 / 32 |
| 표현 풍부 | 소설·수필·세계 내부 구술 | 0.72 / 0.90 / 44 |

사용자는 frequency/presence penalty를 포함한 값을 이번 플레이북에만 덮어쓸 수 있다. Planner는 strict JSON을 위해 고정 설정을 유지하며, Finalizer는 선택한 프로필에서 보수적인 상한을 파생한다. Sampling Profile에는 `max_tokens`, 목표 글자 수, 전개 규칙, 문체 지시를 넣지 않는다.

## 8. 작문 감사

### Canon Auditor

- 출처 없는 고유 사실
- 다른 네임스페이스의 혼입
- 확정 사실과 추론 혼동
- 시대·관계 충돌
- 폐기 설정 사용

### Discourse Auditor

- 추상 설명만 연속됨
- 같은 결론 반복
- 규모 변화 없이 평면적으로 나열
- 사례가 설명을 증명하지 않음
- 모든 문단에 억지 반전
- 결말이 앞 내용을 단순 요약

### Style Auditor

- 상투어·접속사 반복
- 문장 길이 단조로움
- 추상명사 과다
- 선택한 서술자 위치 이탈
- 참고 표본 문구의 과도한 유사성

## 9. 참고 표본 분석

참고 글은 `DISCOURSE_REFERENCE`로 저장한다. 사실 검색에는 사용하지 않고 다음만 추출한다.

- 문단별 Move
- 스케일 변화: 우주→사회→대상→개인 등
- 확실성 변화: 확정→보고→논쟁→미지
- 정보 밀도
- 문장 길이 패턴
- 전환 방식
- 문단 종결 기능

분석 결과를 사용자가 검토한 뒤 전개 방식과 Voice Profile 후보로 저장한다.

## 10. 문체·필력(Voice Profile)

Voice Profile은 작가 이름이나 작품 모사를 지정하는 칸이 아니라 `reader_effect`, 문장 호흡, 묘사·대화·비유·문단 원칙, 피할 패턴, 점검 기준의 구조화 계약이다. 참고 글의 세계관 사실과 고유명사는 프로필로 가져오지 않는다. 짧은 예시는 직접 작성·허가·퍼블릭 도메인처럼 생성 사용 권리가 확인된 경우에만 Writer에 전달하며, `ANALYSIS_ONLY`는 일반화 분석에만 쓴다.

앱은 예시 원문 없이 규칙만 담은 `장면 중심 소설 문체`, `구체적 성찰 문체`, `근거 중심 보고서 문체`, `현장 증언 문체`, `편집된 설정집 문체`, `청취 중심 로어 문체`, `세계 내부 기록자 문체`, `친근한 전문 해설 문체`를 `project_id=NULL`, `APPROVED`, 읽기 전용 공용 프로필로 제공한다. 사용자는 이를 그대로 선택하거나 프로젝트로 복제해 새 검토 버전으로 수정한다.

우선순위는 `확정 사실·금지 변경 > 사용자가 이번 원고에 쓴 지시 > 결과물 형태·시점·시제 > 전개 방식 > Voice Profile > 예시`다. 문체 선택이 없으면 숨은 프로필을 넣지 않고 `model_default`를 기록한다.
