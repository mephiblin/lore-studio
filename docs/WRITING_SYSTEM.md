# 작문 시스템 명세

## 1. 다섯 층의 분리

Lore Studio의 작문 품질은 다음 네 층을 분리하는 데서 시작한다.

```text
Concept Pages     무엇에 대해 쓸 것인가
Direction Cards   이 프로젝트 글에서 무엇을 강조·금지할 것인가
Writing Recipe    정보를 어떤 순서로 공개할 것인가
Voice Profile     어떤 문장 호흡과 표현 원칙으로 전달할 것인가
Output Profile    어떤 결과물 형태와 매체로 표현할 것인가
```

하나의 자연어 프롬프트로 이 다섯 역할을 뭉치면 재사용과 수정이 어려워지고, 어떤 선택이 결과에 영향을 주었는지 알 수 없게 된다.

## 2. 전개 방식은 목차나 결과물 형태가 아니다

나쁜 레시피:

```text
1. 기원
2. 외형
3. 능력
4. 부작용
5. 결말
```

이 구조는 특정 소재에만 적용된다.

좋은 레시피:

```text
넓은 맥락에서 독자를 위치시킨다.
대상으로 시야를 좁힌다.
확정 사실을 배치한다.
통념으로 설명되지 않는 예외를 추가한다.
추상 설명 뒤에 구체적 사례를 둔다.
사실의 세계관적 의미와 파급을 확대한다.
충분히 설명하되 근본 원인은 완전히 닫지 않는다.
```

이는 유물, 행성, 종족, 전쟁, 기술, 종교, 기관 등 다양한 소재에 재사용할 수 있다.

## 3. 수사적 이동(Rhetorical Move)

레시피는 문단이 수행하는 역할을 Move로 정의한다.

| Move | 기능 |
|---|---|
| `ORIENT` | 시대·장소·사회·우주적 맥락에 독자를 위치시킨다. |
| `NARROW` | 넓은 배경에서 이번 대상으로 초점을 좁힌다. |
| `ANCHOR` | 확정된 핵심 사실이나 관찰을 제시한다. |
| `COMPLICATE` | 기존 설명으로 풀리지 않는 예외·모순·대가를 추가한다. |
| `COMPARE` | 알려진 것과 비교해 낯선 대상을 이해시킨다. |
| `EXEMPLIFY` | 추상 규칙을 사건·사물·개인의 결과로 구체화한다. |
| `ESCALATE` | 위험·규모·시간·사회적 파급을 확대한다. |
| `INTERPRET` | 사실이 세계관에서 갖는 의미를 해석한다. |
| `WITHHOLD` | 근거 없는 해답을 피하고 의도적 미지를 보존한다. |
| `TURN` | 앞서 형성한 기대나 의미를 뒤집는다. |
| `STING` | 짧고 강한 문장으로 절이나 글을 닫는다. |

레시피의 `required_moves`는 카드에 보이는 순서이자 AI가 처음 만드는 글의 흐름에 적용하는 고정 순서이며, 완성 원고 점검도 같은 값을 기준으로 삼는다. 별도의 `카드 표시` 순서는 두지 않는다. 각 Move의 이름과 목적은 위 표의 전역 사전에서 자동 파생하고 사용자가 다시 작성하지 않는다. 방식마다 달라지는 구체적인 구성 의도는 `planner_rules`, 완성 후 확인 기준은 `audit_rules`에 둔다. 사용자가 글의 흐름 화면에서 명시적으로 바꾼 순서는 허용하되, 완성 원고 점검에서 필수 순서와 다른 부분을 경고한다.

## 4. 기본 공유 전개 방식

| 전개 방식 | 실제 필수 Move 순서 |
|---|---|
| 큰 맥락에서 핵심으로 | 배경 설명 → 주제로 초점 이동 → 핵심 사실 제시 → 예외·대가 추가 → 의미 해설 |
| 현재 흔적에서 과거로 | 핵심 사실 제시 → 배경 설명 → 예외·대가 추가 → 파급 확대 → 관점 전환 |
| 목표에서 결과로 | 핵심 사실 제시 → 예외·대가 추가 → 파급 확대 → 관점 전환 → 의미 해설 |
| 증거에서 판단으로 | 핵심 사실 제시 → 비교 → 예외·대가 추가 → 의미 해설 |
| 원인에서 파급으로 | 배경 설명 → 핵심 사실 제시 → 구체적 사례 → 파급 확대 → 의미 해설 |
| 통념에서 재해석으로 | 배경 설명 → 핵심 사실 제시 → 비교 → 예외·대가 추가 → 관점 전환 |

이 여섯 방식은 `project_id=NULL`인 공유 프리셋이다. 사용자는 같은 Move 체계를 사용해 프로젝트 전용 방식을 만들 수 있다. 두 종류 모두 프로젝트의 인물·장소·사건을 내용으로 포함하지 않으며, 세계관 설명 글·소설 장면·영상 내레이션·세계 내부 문서 같은 결과물 형태와도 독립적이다.

## 5. 프로젝트 집필 지침(DirectionCard)의 역할

집필 지침은 무엇을 강조하거나 금지할지 정하고, 전개 방식은 정보를 공개할 순서를 정한다. 둘 다 프로젝트 소유 항목을 가질 수 있지만 역할은 합치지 않는다.

- “큰 맥락 → 핵심 대상 → 사례·예외 → 의미 순서로 써라”는 전개 방식이다.
- “해결책의 실제 효능과 사회적 대가를 함께 보여 줘라”는 프로젝트 집필 지침이다.
- “기억을 먹는 항로와 수도회를 사용하라”는 세계관 자료 선택이다.
- “영상 내레이션으로 6분 분량”은 결과물 형태와 분량 설정이다.

카드는 다음 구조를 가질 수 있다.

```json
{
  "must_include": ["초기 효능은 실제로 유용하다"],
  "avoid": ["효능이 처음부터 거짓이었다는 반전"],
  "sequence": ["도입", "성공", "의존", "대가", "정착"],
  "ending_preference": "완전한 해결보다 지속되는 구조"
}
```

사용자 원문은 항상 보존하고, 구조화 결과는 보조 해석으로 취급한다.

## 6. 결과물 형태(Output Profile)

같은 소재와 레시피도 매체에 따라 다르게 실현한다.

### 설정 글

- 중간~긴 문장
- 높은 정보 밀도
- 문단 단위 논리 전개
- 근거는 내부 메타데이터 또는 각주

### 영상 내레이션

- 발화하기 쉬운 문장
- 한두 문장마다 시각 비트
- 괄호·긴 삽입절 최소화
- 생성 후 TTS 실측 길이로 조정

### 소설 장면

- 장면 내부 시간의 연속성
- 인물 시점과 감각
- 설명보다 행동·대화 비중 증가

## 7. 작문 감사

### Canon Auditor

- 출처 없는 고유 사실
- 다른 네임스페이스의 혼입
- 확정 사실과 추론 혼동
- 시대·관계 충돌
- 폐기 설정 사용

### Discourse Auditor

- 추상 설명만 연속됨
- 같은 결론 반복
- 규모 변화 없이 평면적으로 나열
- 사례가 설명을 증명하지 않음
- 모든 문단에 억지 반전
- 결말이 앞 내용을 단순 요약

### Style Auditor

- 상투어·접속사 반복
- 문장 길이 단조로움
- 추상명사 과다
- 선택한 서술자 위치 이탈
- 참고 표본 문구의 과도한 유사성

## 8. 참고 표본 분석

참고 글은 `DISCOURSE_REFERENCE`로 저장한다. 사실 검색에는 사용하지 않고 다음만 추출한다.

- 문단별 Move
- 스케일 변화: 우주→사회→대상→개인 등
- 확실성 변화: 확정→보고→논쟁→미지
- 정보 밀도
- 문장 길이 패턴
- 전환 방식
- 문단 종결 기능

분석 결과를 사용자가 검토한 뒤 전개 방식과 Voice Profile 후보로 저장한다.

## 9. 문체·필력(Voice Profile)

Voice Profile은 작가 이름이나 작품 모사를 지정하는 칸이 아니라 `reader_effect`, 문장 호흡, 묘사·대화·비유·문단 원칙, 피할 패턴, 점검 기준의 구조화 계약이다. 참고 글의 세계관 사실과 고유명사는 프로필로 가져오지 않는다. 짧은 예시는 직접 작성·허가·퍼블릭 도메인처럼 생성 사용 권리가 확인된 경우에만 Writer에 전달하며, `ANALYSIS_ONLY`는 일반화 분석에만 쓴다.

우선순위는 `확정 사실·금지 변경 > 사용자가 이번 원고에 쓴 지시 > 결과물 형태·시점·시제 > 전개 방식 > Voice Profile > 예시`다. 문체 선택이 없으면 숨은 프로필을 넣지 않고 `model_default`를 기록한다.
