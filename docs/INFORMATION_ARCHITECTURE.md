# Lore Studio 정보 구조

## 한 문장 구조

사용자는 **프로젝트를 선택하고 → 세계관 자료를 정리하고 → 글에 쓸 자료와 전개 방식을 선택하고 → 초안을 편집하고 → 완성본을 로어북에 보관한다.**

내부 구현 명칭은 API와 개발 문서에 남길 수 있지만, 기본 화면은 사용자가 하려는 작업의 이름을 사용한다.

## 전역 메뉴

| 메뉴 | 경로 | 사용자의 질문 | 포함하는 것 |
| --- | --- | --- | --- |
| 프로젝트 | `/` | 어느 세계에서 작업할까? | 프로젝트 선택·생성, 모델 연결 상태 |
| 세계관 자료 | `/editor` | 이 세계에는 무엇이 있나? | 프로젝트별 자료 종류, 설정 자료, 자료 간 연결, 집필 지침, 전개 방식 |
| 글 만들기 | `/playbook` | 무엇을 어떤 방식으로 쓸까? | 주제·배경·요소·갈등, 집필 지침, 공용·프로젝트 전개 방식, 결과물 형태, 사용할 설정, 글의 흐름 |
| 원고 작업 | `/documents` | 초안을 어떻게 완성할까? | 초안 편집 → 수정 가능한 완성 설정 → 완성본 만들기 |
| 로어북 | `/lorebook` | 완성된 글은 어디에 있나? | 완성본 읽기·수정·내보내기, 출처 초안 확인 |

## 핵심 객체와 경계

- **프로젝트**: 하나의 세계관과 그 자료·원고를 격리하는 최상위 범위다. 모든 주요 화면에서 선택하고 새로 만들 수 있다.
- **자료 종류(Category Definition)**: 각 프로젝트가 소유하는 세계관 자료 분류다. 새 프로젝트의 시작용 종류도 생성 직후 프로젝트 소유가 되며 카드에서 이름을 바꿀 수 있다. 별도 분류 기준은 두지 않고 이름 자체를 기준으로 쓰며, 내부 key는 이름을 바꿔도 유지된다.
- **세계관 자료(Concept Page)**: 사용자가 만든 종류에 속해 세계를 설명하는 자유 본문이다. 자유 본문이 기본이며 종류·태그·구조화 필드는 보조 정보다.
- **자료 연결(Concept Relation)**: 두 자료의 관계다. 화면에는 ID가 아니라 두 자료의 이름과 자연어 관계를 표시한다.
- **프로젝트 집필 지침(Direction Card)**: 현재 프로젝트에서 반복해 쓸 강조점·금지 사항·결말 원칙이다. 세계의 사실도 보편적인 전개 패턴도 아니다.
- **전개 방식(Writing Recipe)**: 정보를 공개하는 순서다. `project_id=NULL`인 공용 기본 방식과 각 프로젝트에서 생성·수정하는 전용 방식이 있으며, 글 만들기에는 공용 방식과 현재 프로젝트 방식만 함께 표시한다.
- **결과물 형태(Output Profile)**: 세계관 설명 글, 소설 장면 등 완성본의 종류다. 전개 방식과 별개다.
- **글 만들기 기록(Playbook Session)**: 선택 자료, 집필 지침, 전개 방식, 결과물 형태, 시점·시제, 분량, seed를 저장해 생성 과정을 재현한다.
- **초안(Draft Document)과 문단(LoreBlock)**: 글 만들기에서 생성되고 원고 작업에서 편집하는 결과다. 초안에서 발견된 새 설정은 설정 후보일 뿐이며 사용자가 승인하기 전까지 정식 설정이 아니다.

## UI 용어 사전

| 개념 | 화면 표기 | 사용 규칙 |
| --- | --- | --- |
| Concept Page | 세계관 자료 | `프로젝트 자료`, `컨셉`으로 바꾸어 부르지 않는다. |
| Category Definition | 자료 종류 | 화면에서 `카테고리`, `타입`과 혼용하지 않는다. 프로젝트 안에서만 관리한다. |
| Direction Card | 집필 지침 | 프로젝트별 강조점·금지 원칙에만 쓴다. |
| Writing Recipe | 전개 방식 | `전개 패턴`, `전개 방향`, `레시피`는 내부 설명에서만 쓴다. |
| Output Profile | 결과물 형태 | 종류 입력은 `결과물 종류`로 표시하고 `글 형태`와 혼용하지 않는다. |
| Draft Document | 초안 | AI 생성 결과와 원고 작업의 편집 대상을 뜻한다. |
| Final Document | 완성본 | 다듬기를 마쳐 로어북에 저장할 글을 뜻한다. |
| Candidate | 설정 후보 | 사용자 승인 전 새 설정에만 쓴다. |
| Project Canon | 정식 설정 | `정사`처럼 별도 학습이 필요한 표현은 쓰지 않는다. |
| Lorebook | 로어북 | 완성본이 저장되는 전역 장소 이름으로만 쓴다. |

## 화면 원칙

1. 글 만들기는 `주제 → 배경 → 주요 요소 → 갈등·변수 → 집필 지침 → 전개 방식 → 결과물 형태 → 확인·작성`의 순서형 질문으로 구성한다. 한 화면에는 현재 질문의 선택 동작만 표시한다.
2. 주제는 한 개가 필수이고 나머지 자료 역할은 선택 사항이다. 선택하지 않은 단계는 명시적인 건너뛰기 문구로 넘긴다.
3. 앞 단계에서 역할이 정해진 자료는 뒤 역할 후보에서 제외한다. 상단 단계 표시가 선택 자료명이나 선택 개수를 함께 보여 주며, 별도의 중복 요약 패널을 두지 않는다. 완료한 단계는 이 표시나 최종 검토에서 다시 열 수 있다.
4. 최종 검토 뒤에는 `사용할 설정 확인 → 글의 흐름 만들기 → 초안 작성` 순서를 UI와 비활성 상태로 드러내고, 각 단계에 쉬운 설명을 둔다.
5. UUID, enum, 모델 별칭, namespace, 토큰 같은 내부 정보는 기본 정보 계층에서 숨기거나 자연어로 번역한다.
6. 관계, 집필 지침, 전개 방식, 설정 후보는 각각 무엇을 바꾸는지와 무엇을 바꾸지 않는지 가까운 위치에서 설명한다.
7. 프로젝트 선택은 화면을 이동해도 유지한다. 원고 작업에서는 미저장 초안을 먼저 저장하고, 늦게 끝난 이전 프로젝트 요청이 현재 선택을 덮지 못하게 한다.
8. 원고 생성 완료 시 생성된 원고를 직접 가리키는 편집 화면으로 이동한다. 모바일에서는 문서 목록을 선택 메뉴로 줄이고 원고 본문을 먼저 읽고 편집할 수 있게 한다.
9. 원고 작업은 `1. 초안 편집 → 2. 완성 설정 → 3. 완성본 만들기`를 한 단계씩 보여 준다. 이전 글 만들기 기록의 값은 완성 설정의 초깃값이며 사용자가 다시 수정한다.
10. 완성본은 초안의 필드가 아니라 `document_kind=lorebook`인 별도 문서로 저장하고 상단 `로어북`에서만 읽고 편집한다. 출처 초안 ID와 해시로 계보와 오래된 상태를 표시한다.
11. 모바일 전역 메뉴와 단계 표시는 가로 스크롤에 의존하지 않는다. 전역 메뉴는 하단 5칸, 글 만들기 단계는 2열, 원고 작업 단계는 3열 안에서 모두 보여 준다.
12. 모바일 세계관 자료 목록에서 항목을 선택하면 변경된 본문 편집기로 즉시 이동해 선택 결과를 확인할 수 있게 한다.
13. 초안 편집의 제목·상태·모든 문단은 하나의 저장 단위다. 저장하지 않은 상태를 명시하고 다음 단계, 다른 초안, 다른 프로젝트로 이동하기 전에 저장한다.
14. 글 만들기의 자료 선택은 아직 다른 역할에 배정하지 않은 전체 자료를 보여 주고 18개씩 점진적으로 연다. 검색과 자료 종류 필터는 현재 단계에서 같은 전체 범위를 대상으로 한다.
15. 대규모 자료 목록은 데스크톱과 모바일 모두 화면 안의 독립 스크롤 영역으로 제한한다. 자료 수가 늘어나도 다음 단계와 주요 동작을 페이지 수만 픽셀 아래로 밀어내지 않는다.
16. 프로젝트 생성은 모바일에서 하단 메뉴 위에 완전히 들어오는 대화상자로 열고, 바깥 영역·닫기 버튼·Escape로 취소한다.
17. 로어북은 읽기 모드가 기본이다. 제목과 본문은 줄바꿈되는 문서로 렌더링하고, 사용자가 `글 편집`을 선택한 동안에만 입력란과 저장 동작을 노출한다.
18. 모바일 초안은 본문 위의 `원고 도구 보기`로 부분 재작성·점검·설정 후보에 바로 이동하며, 부분 재작성 결과가 생기면 그 비교 영역으로 자동 이동한다.
19. `세계관 자료`의 로컬 탭은 `세계관 자료 / 자료 종류 / 집필 지침 / 전개 방식`으로 나눈다. 종류 생성·이름 변경은 `자료 종류`의 프로젝트 카드형 갤러리에서만 한다. `전개 방식`은 현재 프로젝트와 관계없이 공용 기본 방식을 항상 노출하고, 현재 프로젝트 전용 정보 공개 순서를 같은 카드형 목록에서 생성·수정·안전 삭제한다. 전개 카드에는 별도 홍보용 단계를 만들지 않고 실제 `required_moves` 순서를 번호로 표시하며 단계 목적은 Move에서 자동 파생한다.
20. 데스크톱 전역 메뉴는 사용자가 접고 펼칠 수 있으며, 접힌 상태에서도 현재 위치와 다섯 목적지는 식별 가능해야 한다. 선택 상태는 다음 방문에도 유지한다.
21. 프로젝트 허브를 제외한 작업 화면은 브라우저 높이를 작업 영역으로 사용한다. 프로젝트 선택, 로컬 메뉴, 단계 표시와 글 만들기의 하단 `이전 / 계속` 이동 바는 고정하고 현재 작업의 목록·본문·검토 도구가 각자 독립적으로 스크롤한다. 글 만들기 이동 바는 `.playbook-workspace` 바깥의 형제 영역이어야 한다.
22. 세계관 자료의 `자료 목록 / 본문 / 핵심 정보`, 원고 작업의 `초안 / 원고 도구`, 로어북의 `책장 / 읽기 영역`은 데스크톱에서 동시에 보이는 형제 패널이다. 한 패널의 긴 내용이 다른 패널의 위치를 밀어내지 않는다.
23. 모바일에서는 고정 다중 패널을 강제하지 않는다. 하단 전역 메뉴를 유지하고 로컬 패널을 한 열의 자연스러운 문서 흐름으로 바꾸되, 긴 선택 목록만 제한된 높이 안에서 독립 스크롤한다.
24. 세계관 자료 화면의 프로젝트 선택과 `세계관 자료 / 자료 종류 / 집필 지침 / 전개 방식` 로컬 메뉴는 하나의 명령줄을 공유한다. 자료 제목·한 줄 요약은 본문 바로 위에서 편집하고, 핵심 정보에는 자료 종류·태그·원고에서 지킬 사실 경계·자료 연결만 둔다. 권위 역할, 시대, 연속성 같은 내부 메타데이터는 기본 편집 화면에 노출하지 않는다.
24-1. 원고 작성 경계는 `유지할 사실 / 공개 유보 / 금지된 변경·전개`로 구분한다. 본문 기반 AI 제안은 근거 구절과 함께 검토한 후에만 입력하며 자동 저장하지 않는다. 연결된 자료는 작성 경계가 아니므로 별도 영역에 둔다.
24-2. 세계관 자료 본문의 `AI 수정`은 사용자가 드래그한 범위만 대상으로 하되 전체 본문, 선택부 앞뒤, 작성 경계를 읽기 전용 문맥으로 전달한다. 모델은 문서 주제와 연결 조건을 먼저 구조화한 뒤 대체문을 작성하며, `더 자세히 (약 2배)`는 원문 길이 기반 최소·목표 길이를 적용한다. `AI 작성`의 참고 자료 선택은 이번 생성 입력이며 영구적인 자료 연결과 구분한다. 두 결과는 기존 본문을 즉시 덮지 않는 `CANDIDATE` 제안으로 먼저 보여 주고, 사용자가 본문 반영과 변경 저장을 각각 명시적으로 실행한다.
24-3. `+ 새 자료`는 이름과 자료 종류만 입력받고 일반 세계관 설정(`DRAFT_SETTING`)으로 생성한다. 사실·영감·문체 격리를 위한 내부 사용 역할은 유지하되, 새 설정을 만드는 기본 흐름에 역할 선택을 노출하지 않는다.
25. 설명은 작업 영역을 대신하는 대형 소개 패널로 두지 않는다. 자료 종류·집필 지침·전개 방식의 개념 설명과 글 만들기·원고 작업의 단계별 질문은 정보 버튼의 호버·클릭 툴팁으로 제공한다. 툴팁은 패널 내부가 아닌 화면 최상위 오버레이에 놓아 고정 패널이나 독립 스크롤 영역에 잘리지 않게 한다. 작업면에는 현재 조작과 콘텐츠를 우선한다.
26. 프로젝트 허브는 별도의 `작업 흐름`이나 로컬 모델 상태를 반복하지 않고 프로젝트 선택에 집중한다. 상단 안내는 180px 이하의 콤팩트한 맥락으로 제한한다. 프로젝트는 300px 안팎의 커버 카드로 스캔하며, 16:9 커버·이름·두 줄 설명·`세계관 자료 / 글 만들기`로만 구성한다. 커버 교체·제거는 카드 안의 문맥 동작으로 둔다.
27. 글 만들기의 자료 선택 카드는 프로젝트 갤러리와 동일한 260–300px 폭, 6px 모서리, `16:9 이미지 / 제목·요약 / 하단 메타데이터` 구조를 사용한다. 이미지가 없을 때 썸네일에는 제목을 최대 5자까지 표시한다. 자료 종류·사용 역할·선택 체크는 카드 하단 한 곳에만 두고, `CANON_EVIDENCE`의 카드용 축약 표기는 `사용`으로 한다. 별도 추천 범위를 두지 않고 모든 미배정 자료를 같은 기준으로 보여 준다. 선택 상태는 주요 메뉴와 같은 진한 녹색 바탕과 노란색 텍스트로 구분한다. 집필 지침·전개 방식 선택 카드도 같은 폭과 선택 색상을 따른다.
28. 자료 종류·집필 지침·전개 방식의 목록은 카드 탐색에만 사용한다. 생성과 수정은 `AI 작성`과 같은 모달 작업면에서 열고, 배경 차단·제목과 닫기·내부 스크롤 폼·고정 취소/저장의 계층을 공유한다. 집필 지침의 `세부 규칙 직접 작성`은 접지 않고 전체 입력 필드를 바로 보여 준다.
