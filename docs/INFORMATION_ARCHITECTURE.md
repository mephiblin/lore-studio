# Lore Studio 정보 구조

## 한 문장 구조

사용자는 **프로젝트를 선택하고 → 세계관 자료를 정리하고 → 글에 쓸 자료와 전개 방식을 선택하고 → 초안을 편집하고 → 완성본을 로어북에 보관한다.**

내부 구현 명칭은 API와 개발 문서에 남길 수 있지만, 기본 화면은 사용자가 하려는 작업의 이름을 사용한다.

## 전역 메뉴

| 메뉴 | 경로 | 사용자의 질문 | 포함하는 것 |
| --- | --- | --- | --- |
| 프로젝트 | `/` | 어느 세계에서 작업할까? | 프로젝트 선택·생성, 모델 연결 상태 |
| 세계관 자료 | `/editor` | 이 세계에는 무엇이 있나? | 프로젝트별 자료 종류, 설정 자료, 자료 간 연결, 프로젝트 집필 지침 |
| 글 만들기 | `/playbook` | 무엇을 어떤 방식으로 쓸까? | 주제·배경·요소·갈등, 집필 지침, 공유 전개 방식, 결과물 형태, 사용할 설정, 글의 흐름 |
| 원고 작업 | `/documents` | 초안을 어떻게 완성할까? | 초안 편집 → 수정 가능한 완성 설정 → 완성본 만들기 |
| 로어북 | `/lorebook` | 완성된 글은 어디에 있나? | 완성본 읽기·수정·내보내기, 출처 초안 확인 |

## 핵심 객체와 경계

- **프로젝트**: 하나의 세계관과 그 자료·원고를 격리하는 최상위 범위다. 모든 주요 화면에서 선택하고 새로 만들 수 있다.
- **자료 종류(Category Definition)**: 각 프로젝트가 소유하는 세계관 자료 분류다. 새 프로젝트의 시작용 종류도 생성 직후 프로젝트 소유가 되며 이름·설명·글 만들기 추천 위치를 바꿀 수 있다. 내부 key는 이름을 바꿔도 유지된다.
- **세계관 자료(Concept Page)**: 사용자가 만든 종류에 속해 세계를 설명하는 자유 본문이다. 자유 본문이 기본이며 종류·태그·구조화 필드는 보조 정보다.
- **자료 연결(Concept Relation)**: 두 자료의 관계다. 화면에는 ID가 아니라 두 자료의 이름과 자연어 관계를 표시한다.
- **프로젝트 집필 지침(Direction Card)**: 현재 프로젝트에서 반복해 쓸 강조점·금지 사항·결말 원칙이다. 세계의 사실도 보편적인 전개 패턴도 아니다.
- **공유 전개 방식(Writing Recipe)**: 프로젝트와 무관하게 재사용하는 정보 공개 순서다. `큰 맥락 → 핵심 대상 → 사례·예외 → 의미`처럼 글을 써 내려가는 패턴을 정한다.
- **결과물 형태(Output Profile)**: 세계관 설명 글, 소설 장면 등 완성본의 종류다. 전개 방식과 별개다.
- **글 만들기 기록(Playbook Session)**: 선택 자료, 집필 지침, 전개 방식, 결과물 형태, 시점·시제, 분량, seed를 저장해 생성 과정을 재현한다.
- **초안(Draft Document)과 문단(LoreBlock)**: 글 만들기에서 생성되고 원고 작업에서 편집하는 결과다. 초안에서 발견된 새 설정은 설정 후보일 뿐이며 사용자가 승인하기 전까지 정식 설정이 아니다.

## UI 용어 사전

| 개념 | 화면 표기 | 사용 규칙 |
| --- | --- | --- |
| Concept Page | 세계관 자료 | `프로젝트 자료`, `컨셉`으로 바꾸어 부르지 않는다. |
| Category Definition | 자료 종류 | 화면에서 `카테고리`, `타입`과 혼용하지 않는다. 프로젝트 안에서만 관리한다. |
| Direction Card | 집필 지침 | 프로젝트별 강조점·금지 원칙에만 쓴다. |
| Writing Recipe | 전개 방식 | `전개 패턴`, `전개 방향`, `레시피`는 내부 설명에서만 쓴다. |
| Output Profile | 결과물 형태 | 종류 입력은 `결과물 종류`로 표시하고 `글 형태`와 혼용하지 않는다. |
| Draft Document | 초안 | AI 생성 결과와 원고 작업의 편집 대상을 뜻한다. |
| Final Document | 완성본 | 다듬기를 마쳐 로어북에 저장할 글을 뜻한다. |
| Candidate | 설정 후보 | 사용자 승인 전 새 설정에만 쓴다. |
| Project Canon | 정식 설정 | `정사`처럼 별도 학습이 필요한 표현은 쓰지 않는다. |
| Lorebook | 로어북 | 완성본이 저장되는 전역 장소 이름으로만 쓴다. |

## 화면 원칙

1. 글 만들기는 `주제 → 배경 → 주요 요소 → 갈등·변수 → 집필 지침 → 전개 방식 → 결과물 형태 → 확인·작성`의 순서형 질문으로 구성한다. 한 화면에는 현재 질문의 선택 동작만 표시한다.
2. 주제는 한 개가 필수이고 나머지 자료 역할은 선택 사항이다. 선택하지 않은 단계는 명시적인 건너뛰기 문구로 넘긴다.
3. 앞 단계에서 역할이 정해진 자료는 뒤 역할 후보에서 제외한다. 상단 단계 표시가 선택 자료명이나 선택 개수를 함께 보여 주며, 별도의 중복 요약 패널을 두지 않는다. 완료한 단계는 이 표시나 최종 검토에서 다시 열 수 있다.
4. 최종 검토 뒤에는 `사용할 설정 확인 → 글의 흐름 만들기 → 초안 작성` 순서를 UI와 비활성 상태로 드러내고, 각 단계에 쉬운 설명을 둔다.
5. UUID, enum, 모델 별칭, namespace, 토큰 같은 내부 정보는 기본 정보 계층에서 숨기거나 자연어로 번역한다.
6. 관계, 집필 지침, 전개 방식, 설정 후보는 각각 무엇을 바꾸는지와 무엇을 바꾸지 않는지 가까운 위치에서 설명한다.
7. 프로젝트 선택은 화면을 이동해도 유지한다. 원고 작업에서는 미저장 초안을 먼저 저장하고, 늦게 끝난 이전 프로젝트 요청이 현재 선택을 덮지 못하게 한다.
8. 원고 생성 완료 시 생성된 원고를 직접 가리키는 편집 화면으로 이동한다. 모바일에서는 문서 목록을 선택 메뉴로 줄이고 원고 본문을 먼저 읽고 편집할 수 있게 한다.
9. 원고 작업은 `1. 초안 편집 → 2. 완성 설정 → 3. 완성본 만들기`를 한 단계씩 보여 준다. 이전 글 만들기 기록의 값은 완성 설정의 초깃값이며 사용자가 다시 수정한다.
10. 완성본은 초안의 필드가 아니라 `document_kind=lorebook`인 별도 문서로 저장하고 상단 `로어북`에서만 읽고 편집한다. 출처 초안 ID와 해시로 계보와 오래된 상태를 표시한다.
11. 모바일 전역 메뉴와 단계 표시는 가로 스크롤에 의존하지 않는다. 전역 메뉴는 하단 5칸, 글 만들기 단계는 2열, 원고 작업 단계는 3열 안에서 모두 보여 준다.
12. 모바일 세계관 자료 목록에서 항목을 선택하면 변경된 본문 편집기로 즉시 이동해 선택 결과를 확인할 수 있게 한다.
13. 초안 편집의 제목·상태·모든 문단은 하나의 저장 단위다. 저장하지 않은 상태를 명시하고 다음 단계, 다른 초안, 다른 프로젝트로 이동하기 전에 저장한다.
14. 글 만들기의 자료 선택은 프로젝트 자료 종류에 저장된 추천 위치를 기준으로 현재 단계의 추천 범위를 먼저 보여 주고 18개씩 점진적으로 연다. 검색은 전체 범위를 찾으며 사용자는 언제든 `추천 / 전체`를 전환할 수 있다.
15. 대규모 자료 목록은 데스크톱과 모바일 모두 화면 안의 독립 스크롤 영역으로 제한한다. 자료 수가 늘어나도 다음 단계와 주요 동작을 페이지 수만 픽셀 아래로 밀어내지 않는다.
16. 프로젝트 생성은 모바일에서 하단 메뉴 위에 완전히 들어오는 대화상자로 열고, 바깥 영역·닫기 버튼·Escape로 취소한다.
17. 로어북은 읽기 모드가 기본이다. 제목과 본문은 줄바꿈되는 문서로 렌더링하고, 사용자가 `글 편집`을 선택한 동안에만 입력란과 저장 동작을 노출한다.
18. 모바일 초안은 본문 위의 `원고 도구 보기`로 부분 재작성·점검·설정 후보에 바로 이동하며, 부분 재작성 결과가 생기면 그 비교 영역으로 자동 이동한다.
19. `세계관 자료`의 로컬 탭은 `세계관 자료 / 자료 종류 / 집필 지침`으로 나눈다. 종류 생성·이름 변경·추천 위치 지정은 `자료 종류`에서만 하고, 자료 작성 화면에는 현재 프로젝트의 종류 선택만 노출한다.
