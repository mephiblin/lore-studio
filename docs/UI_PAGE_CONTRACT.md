# 현재 페이지 UI 양식 기준서

이 문서는 Lore Studio의 **현재 구현을 기준으로 한 페이지별 UI 계약**입니다. 새 화면 시안이 아니라, 기능 수정 뒤 레이아웃·정보 계층·상태 표현이 훼손되었는지 판단하는 기준선입니다. 실제 구조가 의도적으로 바뀌면 코드, 이 문서, `INFORMATION_ARCHITECTURE.md`, 관련 Playwright 검증을 같은 변경에서 갱신합니다.

반복 점검은 프로젝트 로컬 [`$lore-studio-ui-safety`](../.codex/skills/lore-studio-ui-safety/SKILL.md) 절차를 사용합니다. 페이지 역할·레이아웃·스크롤·상태 표현이 바뀌면 이 기준서를 갱신하고, 점검 route·명령·기준 문서 위치 자체가 바뀌면 skill과 정적 검사기도 함께 갱신합니다.

## 1. UI·정보 구조 명제

사용자는 먼저 **프로젝트(하나의 세계관)**를 선택하고, 그 안에서 자료를 축적한 뒤 글을 설계하고, 초안을 편집하고, 완성본을 로어북에 보관합니다. 따라서 전체 구조는 프로젝트를 중심 객체로 삼고, 주요 메뉴는 작업 생명주기 순서로 고정합니다.

```text
01 프로젝트
   └─ 현재 프로젝트
      ├─ 02 세계관 자료
      │  ├─ 세계관 자료
      │  ├─ 자료 종류
      │  ├─ 집필 지침
      │  ├─ 전개 방식
      │  └─ 문체·필력
      ├─ 03 글 만들기
      │  └─ 선택 8단계 → 확인·작성
      ├─ 04 원고 작업
      │  └─ 초안 편집 → 완성 다듬기 → 완성본 만들기
      └─ 05 로어북
         └─ 완성본 읽기·명시적 편집·내보내기
```

상위 메뉴는 장소를 나타내는 명사형 레이블을 사용합니다. 버튼은 `글 편집`, `변경 저장`, `자료 삭제`, `초안 작성`처럼 실행 결과를 예측할 수 있는 동사형 레이블을 사용합니다.

## 2. 공통 시각 언어

### 색상

| 역할 | 토큰·현재 값 | 사용 규칙 |
|---|---|---|
| 본문 잉크 | `--ink #18302c` | 제목, 핵심 본문, 강한 정보 |
| 보조 녹색 | `--ink-soft #29534d` | 기본 primary 버튼 |
| 앱 배경 | `--fog #e8edea` | 전체 작업실 배경 |
| 종이 | `--paper #fbfaf5` | 카드·문서 작업면 |
| 종이 보조 | `--paper-deep #f4f0e6` | command bar·footer·보조 영역 |
| 주요 메뉴 | `--nav-deep #14322e` | 좌측 메뉴, 어두운 결과 견본 |
| 선택 배경 | `--nav-active #20423e` | 선택된 카드·메뉴 |
| 아이덴티티 금색 | `--nav-accent #f0bc65` | 어두운 면의 선택 텍스트·진행 강조 |
| 주의 강조 | `--signal #b85f36` | 활성 메뉴 선, 제한적인 강조 |
| 위험 | `--danger #ad534d` | 삭제·파괴적 동작 |

- 녹색은 브랜드 색이면서 상태 색입니다. **완료 녹색은 실제 성공한 단계에만** 사용합니다.
- 남색·진녹색 배경의 핵심 텍스트는 흰색 또는 금색을 사용합니다.
- 삭제는 위험색 테두리와 텍스트를 사용하며 primary 버튼과 같은 면적·위계를 갖지 않습니다.

### 글꼴과 계층

- 화면·입력·버튼: `Pretendard`, `Noto Sans KR`, 시스템 sans-serif.
- 페이지·카드의 서사적 제목: `Georgia`, `Noto Serif KR`, serif.
- 순서, eyebrow, 짧은 상태 기호: monospace. 실제 순서나 상태를 표현할 때만 사용합니다.
- 설명 문장은 작업면의 제목보다 작고 옅어야 하며, 별도 대형 소개 header로 본문을 밀어내지 않습니다.

### 모서리와 표면

- 입력·버튼: 4px.
- 프로젝트·자료 선택·설정 카드: 6px.
- 일반 카드: 8px.
- 큰 작업면·modal: 9px 안팎.
- 그림자와 hover 상승은 카드 경계를 보조하는 수준으로 제한합니다. 글쓰기 본문보다 장식이 강해지지 않습니다.

### 버튼 위계

| 종류 | 역할 | 한 작업면의 원칙 |
|---|---|---|
| `.primary` | 저장, 계속, 생성처럼 현재 흐름의 핵심 동작 | 가능하면 1개 |
| `.secondary` | 편집 진입, 보조 실행, 내보내기 | primary보다 낮은 위계 |
| `.ghost` | 이전, 취소, 닫기, 낮은 위험의 보조 동작 | 배경 경쟁 금지 |
| `.danger-button` | 삭제와 되돌릴 수 없는 동작 | 대상 이름·영향 확인 필요 |

## 3. 전역 앱 셸

### 데스크톱

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 좌측 주요 메뉴 │ 현재 내부 페이지가 차지하는 주 작업면             │
│ 236px / 64px │                                              │
│ 접기·펼치기    │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- `.app-shell`은 좌측 메뉴와 `.app-main`의 2열 grid입니다.
- `.app-nav`는 viewport 높이를 차지하고 자체 스크롤 없이 고정됩니다.
- 펼친 폭은 236px, 접힌 폭은 64px입니다. 접힘 상태에서도 현재 위치와 펼치기 버튼을 식별할 수 있어야 합니다.
- 주요 메뉴 아래에 정적 상태 점이나 보안 설명 패널을 두지 않습니다.
- 본문이 주인공입니다. 좌측 메뉴가 접히면 확보한 폭을 `.app-main`이 즉시 사용합니다.
- 내부 작업 페이지는 브라우저 전체보다 자신의 작업면에서 스크롤하는 것을 우선합니다.

### 모바일

- 주요 메뉴는 최대 5개의 하단 목적지로 전환합니다.
- 하단 메뉴 위에 페이지의 핵심 CTA와 마지막 입력이 가려지지 않는 안전 여백을 둡니다.
- 좌측 메뉴용 접기 버튼과 상태 설명은 모바일 주 작업면을 차지하지 않습니다.
- command bar의 프로젝트 선택과 `+ 새 프로젝트`는 360px에서도 한 행을 유지합니다. 글 만들기 9단계는 5+4 두 행, 원고 작업 3단계는 한 행으로 보여 본문 위치를 불필요하게 내리지 않습니다.

## 4. 공통 작업면 양식

| UI 역할 | 구현 기준 class | 계약 |
|---|---|---|
| 페이지 범위 | `.page` | 최대 폭 1540px, 중앙 정렬 |
| 앱형 작업 페이지 | `.workspace-page` | viewport 안에서 command bar·본문·footer의 높이 관계 유지 |
| 상단 command bar | `.page-tools` | 현재 프로젝트와 로컬 탭·단계를 한 줄에 결합 |
| 프로젝트 선택 | `.project-tools` | 현재 작업 namespace를 항상 확인 가능 |
| 로컬 탭 | `.section-tabs` | 한 섹션 안의 3–7개 동급 화면 전환 |
| 단계 표시 | `.wizard-progress` | 실제 순서가 있는 흐름에만 사용 |
| 큰 작업면 | `.wizard-shell` | 본문과 내부 스크롤의 경계 |
| 하단 이동 | `.wizard-actions` | 현재 단계의 이전·계속·저장 동작, 본문과 분리 |
| 생성·수정 창 | `.settings-modal` | header 고정, body만 스크롤, footer 고정 |
| 빈 상태 | `.empty-state` | 무엇이 비었는지와 다음 행동을 함께 안내 |

- `.page-tools`는 빈 장식 영역으로 존재하지 않습니다. 로컬 탭·단계와 프로젝트 선택을 함께 수용합니다.
- tooltip은 다른 패널의 overflow에 잘리지 않는 viewport 기준 overlay입니다.
- modal은 배경을 차단하고, 닫기·취소·저장의 세 경로와 고정 footer를 가집니다.
- 긴 목록, 본문, inspector 중 어디가 스크롤을 소유하는지 페이지마다 하나씩 명확히 정의합니다.

## 5. 01 프로젝트 `/`

### 페이지 역할

프로젝트를 만들고, 커버와 개요를 보고, 해당 세계관의 자료 또는 글 만들기로 진입하는 **프로젝트 허브**입니다.

### 현재 골격

```text
간결한 오늘의 작업 요약
프로젝트 제목·새 프로젝트
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 16:9 커버 │ │ 16:9 커버 │ │ 16:9 커버 │
│ 이름·설명 │ │ 이름·설명 │ │ 이름·설명 │
│ 자료 글 삭제│ │ 자료 글 삭제│ │ 자료 글 삭제│
└──────────┘ └──────────┘ └──────────┘
```

- `.home-thesis`는 짧은 진입 안내이며 카드보다 시각적으로 커지지 않습니다.
- `.project-grid`는 260–300px 카드의 좌측 정렬 갤러리입니다. 카드가 viewport를 불필요하게 가득 채우지 않습니다.
- `.project-card`는 `16:9 커버 → 제목·2줄 설명 → 문맥 동작` 순서입니다.
- 커버가 없으면 프로젝트 이름 앞부분을 최대 16자까지 사용하고, 8자를 넘으면 8자씩 두 줄로 나눈 fallback을 보여 줍니다.
- 카드 전체를 모호한 링크로 만들지 않고 `세계관 자료`, `글 만들기`, `삭제`의 결과를 분리합니다.
- 삭제는 가장 낮은 위험 위계로 배치하며 커버·본문보다 먼저 눈에 띄지 않습니다.
- 빈 상태는 새 프로젝트 만들기를 직접 제공합니다.

### 허용하지 않는 변형

- 카드 폭을 다시 대형 dashboard 타일처럼 늘리는 것.
- 로컬 모델 상태판이나 작업 흐름 설명판을 프로젝트 카드보다 앞세우는 것.
- 이미지 위의 긴 본문, 의미 없는 통계, 중복 진입 버튼을 추가하는 것.

## 6. 02 세계관 자료 `/editor`

### 페이지 역할

세계의 사실·아이디어를 쓰고, 프로젝트별 분류·집필 원칙·전개·표현 도구를 관리하는 **자료 작업실**입니다.

### 상단 command bar

- `.editor-commandbar` 안에 `세계관 자료 / 자료 종류 / 집필 지침 / 전개 방식 / 문체·필력` 탭과 현재 프로젝트를 함께 둡니다.
- 별도의 대형 페이지 소개 header를 두지 않습니다.
- 탭 이름은 객체의 역할을 유지하며 `설정`, `기타` 같은 포괄 레이블로 합치지 않습니다.

### 세계관 자료 탭

```text
┌─ 자료 목록 300px ─┬─ 읽기·본문 편집 minmax ─────┬─ 핵심 정보 340px ─┐
│ 생성·검색·종류필터  │ 제목·요약·본문·편집 동작       │ 작성 경계·연결·고급  │
│ 독립 목록 스크롤     │ 가장 넓은 주 작업면            │ 독립 inspector 스크롤│
└──────────────────┴───────────────────────────┴───────────────────┘
```

- `.archive-layout`은 데스크톱 3열입니다. 본문 열이 남는 폭을 우선 사용합니다.
- `.archive-list`는 페이지 자체를 밀지 않고 목록 내부가 스크롤됩니다.
- `.manuscript-panel`은 제목·요약·Tiptap 본문이 이어진 하나의 문서 작업면입니다.
- 저장된 자료는 **읽기 모드가 기본**입니다. 제목·요약은 텍스트, 본문 toolbar는 숨김 상태입니다.
- `글 편집`을 누르면 제목·요약·본문·핵심 정보 입력과 AI 동작이 활성화됩니다.
- 본문 toolbar의 `Markdown 편집`은 현재 Tiptap 문서를 Markdown 원문으로 바꾸어 편집하고 `서식 편집`으로 돌아옵니다. 제목, 굵게·기울임·취소선, 목록, 인용, 인라인·블록 코드, 링크, 구분선을 양방향 변환합니다.
- 세계관 자료의 저장 권위는 기존 `body_json`을 유지합니다. Markdown 편집은 저장 형식을 바꾸거나 기존 자료 migration을 요구하지 않으며, AI 제안의 Markdown도 같은 구조로 반영합니다.
- `변경 저장`과 `취소`는 읽기 모드로 돌아갑니다. 새 자료만 생성 직후 편집 모드로 엽니다.
- `.archive-inspector`는 `자료 종류·태그 → 원고 작성 경계 → 연결된 자료 → 고급 정보` 순서입니다.
- `유지할 사실 / 공개 유보 / 금지된 변경·전개`는 도움말을 가지며 `AI 제안`은 저장 전 선택 검토를 거칩니다.
- 본문 안의 `AI 수정` panel과 `AI 작성` modal에는 각각 `Gemma / Qwen` 선택기가 있습니다. 기본값은 Gemma이고 같은 편집 세션에서 마지막 선택을 공유합니다. 선택은 해당 요청에만 적용되며 제안 제목에 실제 모델 이름을 표시하고 다른 모델로 자동 fallback하지 않습니다.
- `AI 작성`은 생성 본문 자체가 결과이므로 JSON 응답 스키마를 요구하지 않습니다. 비어 있지 않은 평문·Markdown을 한 번의 호출로 검토 제안에 표시하며, 과거의 완전한 `content_text` JSON 응답만 호환 차원에서 본문으로 풉니다.
- 자료 삭제는 제목이 보이는 toolbar의 문맥 동작이며 삭제 뒤 안전한 다음 자료 또는 빈 상태를 보여 줍니다.

#### 자료 양산 모달

- 자료 목록의 `자료 양산`은 새 탭이나 즉시 생성 동작이 아니라 `.settings-modal.wide` 안의 2단계 검토 흐름을 엽니다.
- 첫 단계의 기본 정보는 같은 프로젝트의 참고 세계관 자료 1개, 기존 자료 종류 1개, 씨앗 수 6–30개, `간단 / 보통 / 상세` 길이, 추가 지시입니다. 기본 실행 계획은 `Qwen 씨앗 기획 → Gemma 본문 집필 → 최대 동시 작업 4개`이며 한 줄로 먼저 알립니다. 모델과 동시 작업 수 변경은 접힌 `고급 설정`에만 둡니다.
- 기획 에이전트 1개가 `제목 + 간단한 내용 + 차별점 + 참고 근거`를 제안하며 본문이나 자료를 저장하지 않습니다. 사용자는 제목·간단한 내용을 수정하고 1–10개를 선택합니다. 선택 자료 수와 실제 동시 작업 수는 별개이며, 선택하지 않은 씨앗에는 모델 호출을 만들지 않습니다.
- 자료 종류의 템플릿이 있으면 그 속성 이름을, 없으면 음식·괴물·사건·인물·장소·유물 및 일반 자료의 가벼운 작성 설계도를 자동 사용합니다. 빈 구조화 필드를 강제하지 않고 자유 본문이 계속 중심입니다.
- 완성 결과는 제목·요약·본문·태그와 경고를 각각 검토·수정·선택할 수 있습니다. 접힌 품질 정보에서 글자 수, 자료 종류별 핵심 항목, 참고 자료에서 계승한 사실, 새 설정 후보를 확인합니다. `선택한 후보 저장` 전에는 ConceptPage가 생기지 않습니다.
- 저장한 결과도 `usage_role=CANDIDATE`, `authority_state=CANDIDATE`로 남고 자동 정식 설정 승격은 없습니다. 참고 자료·자료 종류·기획/집필 모델·길이·동시 작업 수·추가 지시·씨앗과 개별 호출은 GenerationRun에 남고, 품질 정보는 후보 페이지의 생성 이력에 보존됩니다.
- 일부 본문 에이전트가 실패해도 성공 결과와 실패 이유를 함께 보여 줍니다. 실행 중에는 중복 실행과 모달 닫기를 막고 고정 footer에서 현재 단계의 결정을 유지합니다.
- 모바일 390px와 최소 360px에서는 setup grid가 1열이 되고 씨앗·결과 목록만 modal body에서 스크롤하며 footer는 계속 보입니다.

### 자료 종류·집필 지침·전개 방식·문체·필력 탭

- 모든 목록은 260–300px 계열 카드 또는 내용 밀도에 맞춘 카드 갤러리입니다.
- 제한 높이의 카드 갤러리는 카드 content 높이를 축소하지 않고 목록이 내부 스크롤을 소유합니다.
- 각 화면의 `local-surface-header`는 짧은 제목·도움말·개수·생성 버튼만 가집니다. 긴 `category-intro`형 소개 패널을 두지 않습니다.
- 생성과 수정은 페이지 안에 긴 form을 펼치지 않고 `.settings-modal`에서 처리합니다.
- 집필 지침 카드는 원문 설명과 실제 생성에 쓰는 목표·순서·필수·금지·결말 규칙을 함께 확인할 수 있습니다.
- 전개 방식 카드는 장식용 이미지보다 **필수 문단 순서**를 가장 먼저 보여 줍니다. 단계 목적은 선택한 문단 방식에서 자동 파생됩니다.
- 공용 전개 방식은 모든 프로젝트에서 보이며 읽기 전용, 프로젝트 전개 방식만 수정·삭제할 수 있습니다.
- 문체·필력 카드는 범위, 승인 상태, 버전, 독자 효과를 보여 줍니다. DRAFT와 APPROVED를 같은 상태처럼 표현하지 않습니다.

### 모바일

- 3열은 단일 흐름으로 전환하고 자료 선택은 좁은 picker 또는 상단 목록으로 접근합니다.
- 본문 편집이 먼저이며 inspector는 본문 뒤에서 접근할 수 있어야 합니다.
- 로컬 탭은 줄바꿈으로 높이를 과도하게 키우거나 viewport 가로폭을 넘지 않습니다.
- 자료 본문은 브라우저 문서 스크롤을 사용합니다. 내부 `.editor-content`가 실제로 스크롤되지 않는 상태에서 `overflow:auto`/`overscroll-behavior:contain`으로 터치 제스처를 가로채지 않습니다.
- AI 수정·제안 패널은 긴 선택 문장에도 본문 폭을 늘리지 않고, viewport와 하단 메뉴 사이에서 조작 가능한 sticky 검토면으로 열립니다.
- `AI 작성` modal은 낮아진 모바일 가시 높이에서도 header와 `취소 / 초안 제안` footer를 viewport 안에 유지하고, 지시·위치·모델·분량·참고 자료는 가운데 body 하나에서 스크롤합니다. 참고 자료 목록은 footer 뒤로 겹치지 않아야 하며, 소프트 키보드로 가시 높이가 줄어도 제출 버튼이 눌릴 수 있어야 합니다.

## 7. 03 글 만들기 `/playbook`

### 페이지 역할

세계관 자료와 작성 규칙을 사용자가 명시적으로 고르고, 재현 가능한 입력으로 초안을 만드는 **단계형 설계 작업실**입니다.

### 공통 골격

```text
상단 page-tools: 9단계 + 도움말 | 현재 프로젝트
┌──────────────────────────────────────────────┐
│ 단계별 주 작업면: 카드 선택 / 결과 견본 / 최종 확인  │
└──────────────────────────────────────────────┘
하단 고정: 이전·계속 또는 수정 취소·확인으로 복귀
```

- 단계 표시는 별도 대형 `wizard-heading`이 아니라 `.page-tools` 안에 있습니다.
- 단계 도움말은 각 단계의 `?`에서 hover·click으로 확인합니다.
- `.playbook-workspace`가 주 스크롤을 소유하고 `.playbook-navigation`은 항상 접근 가능한 하단 작업 바입니다.
- 하단 바는 전역 모바일 메뉴 위에 위치하고, 본문 scroll에 섞이지 않습니다.

### 자료·지침·전개·문체 선택 단계

- `.wizard-choice-card`는 프로젝트 카드와 같은 260–300px, 16:9 cover, 제목·요약, 하단 metadata 규격을 따릅니다. 이미지가 없는 자료 커버도 최대 16자·8자씩 두 줄 fallback을 공유합니다.
- 선택 카드는 진한 녹색 배경과 금색 텍스트를 사용하고 체크 상태를 함께 표시합니다.
- 주제만 단일 선택이며 배경·주요 요소·갈등·변수는 복수 선택입니다.
- 이미 다른 역할에 배정한 자료는 중복 노출하지 않습니다.
- 카드 영역은 독립 스크롤하고 `자료 더 보기`는 `.wizard-picker-footer`에 고정합니다.
- `자료 더 보기`는 전역 이전·계속 바와 겹치거나 같은 동작처럼 보이면 안 됩니다.

### 결과물 형태

- `.output-studio`는 `원고 견본 / 선택 카드 deck`의 2열입니다.
- `.output-specimen`은 어두운 종이 견본이며 `원고 설계 / 출력 설정`의 두 장부로 나뉩니다. 원고 설계에는 주제·배경·주요 요소·갈등·변수·집필 지침·전개 방식·문체·필력을 모두 표시하고, 출력 설정에는 형식·시점·시제·분량을 즉시 요약합니다. 선택하지 않은 항목도 `선택 안 함`으로 남겨 누락과 의도적 미선택을 구분합니다.
- 오른쪽에서 선택할 때 왼쪽 견본이 새로고침 없이 바로 바뀝니다.
- 세계관 설명·영상·소설 장면·수필·분석 보고서·세계 내부 문서·세계 내부 구술·자료 큐레이션·해설·상징적 우화 단편을 같은 결과물 형태 카드로 제공합니다.
- `상징적 우화 단편`은 `공간 순례에서 귀결로` 전개와 `의례적 고딕 이야기꾼` 문체를 권장하고, 고정된 반복 신호·선택 근거만의 정사 경계·상징 직접 해설 금지를 적용합니다.
- `세계 내부 구술`은 제한된 화자의 지식 경로와 완성 원고 형식만 지정합니다. 별도 최대 토큰·고정 글자 수는 두지 않고 기존 분량 카드를 공유합니다.
- 결과물 종류, 시점, 시제, 분량은 의미 설명이 있는 카드입니다. 일반 select 묶음으로 퇴행하지 않습니다.
- 분량 다음에는 `정밀 / 균형 / 표현 풍부` 생성 성향 카드가 있습니다. 선택한 결과물 형태의 권장 성향을 기본으로 쓰되 사용자가 명시적으로 바꿀 수 있습니다.
- `고급 샘플링 조정`은 접힌 상태가 기본이며 온도·Top P·Top K·반복 억제·새 화제 허용만 노출합니다. 최대 토큰과 고정 글자 수를 이 영역에 중복 추가하지 않습니다.
- 고급 값을 비우거나 `권장값으로 되돌리기`를 누르면 현재 생성 성향의 값으로 복귀합니다. 실제 적용 키·버전·파라미터는 GenerationRun에 스냅샷으로 남습니다.
- `선택 자료 본문 반영`은 자동 관련 자료 검색이 아니라 주제를 포함해 사용자가 고른 자료의 본문 포함량입니다. 선택 자료가 없으면 `core`로 비활성화합니다.

### 확인·작성

- `.review-workbench`는 왼쪽의 고정 `.output-specimen`과 오른쪽 생성 desk의 2열입니다. 왼쪽은 결과물 형태 단계와 같은 `원고 설계 / 출력 설정` 장부를 그대로 유지합니다.
- 오른쪽에는 `글의 흐름 설계 / 초안 작성` 카드 두 개와 하나의 `.review-result-slot`만 둡니다. 흐름 카드를 누르면 그 자리에 편집 가능한 흐름이, 초안 카드를 누르면 같은 자리에 생성 초안이 교체되어 나타납니다.
- 상단의 네 `수정`은 주제·소재, 집필 지침, 전개·문체, 출력 설정으로만 묶습니다. 해당 단계로 진입한 뒤 일반 순차 진행이 아니라 고정 하단의 `수정 완료 · 확인·작성으로 돌아가기`로 복귀합니다.
- `수정 취소`는 확인 진입 전 선택과 생성 상태를 복원합니다.
- `글의 흐름 설계 → 초안 작성`의 두 단계만 사용자 작업으로 보여 줍니다. 유지할 사실·공개 유보·금지된 변경은 흐름 설계 요청 안에서 자동 컴파일하며 별도 버튼으로 중복하지 않습니다.
- 실제 성공한 단계만 완료 녹색입니다. 현재 열어 본 결과 카드는 진녹색·금색, 미실행 단계는 중립색입니다.
- 글의 흐름은 문단 순서, 문단 방식, 설명 내용, 분량, 근거, 잠금을 직접 조정하는 작업 카드이며 머리말에 문단 예산 합계와 결과물 형태에서 고른 목표 글자 수를 함께 표시합니다.

### 모바일

- output 2열과 review 카드 grid는 1열로 바뀝니다.
- 카드 목록, 견본, 하단 바가 서로 가리지 않아야 합니다.
- 390px와 360px 폭에서 단계 이름·도움말·현재 프로젝트가 가로 overflow를 만들지 않습니다.
- 로어북 상단 테마 선택기는 우측 고정 `모델 연결` 링크의 폭을 예약해 마지막 테마 버튼이 가려지지 않아야 합니다.

## 8. 04 원고 작업 `/documents`

### 페이지 역할

생성된 초안을 문단 단위로 편집하고, 초안의 설계를 유지한 채 필요한 완성도만 보강해 로어북 글로 만드는 **원고 제작 작업실**입니다.

### 상단과 단계

- `.document-commandbar`는 `초안 편집 → 완성 다듬기 → 완성본 만들기` 단계와 현재 프로젝트를 결합합니다.
- `.document-contextbar`에서 현재 작업 초안을 바꿀 수 있고 `저장 안 됨` 상태를 제목 가까이에 표시합니다.
- 단계 이동 시 필요한 저장이 먼저 이루어지며 실패하면 다음 단계로 이동한 것처럼 보이지 않습니다.

### 초안 편집

```text
┌─ 문단 원고 minmax ─────────────────┬─ 원고 도구 330px ─┐
│ 제목·상태·전체 저장                  │ 부분 재작성        │
│ 01 문단 카드 / 02 문단 카드 / …      │ 필력·원고 점검     │
│ 새 문단 추가                         │ 설정 후보 승인     │
└─────────────────────────────────────┴───────────────────┘
하단: 저장 상태 | 저장하고 완성 다듬기로 계속
```

- 문단 카드는 실제 글 순서를 번호로 보여 줍니다.
- 제목 입력·상태·저장·내보내기는 한 줄의 콤팩트 toolbar에서 하단 기준으로 정렬하며, 제목 위아래의 장식성 여백을 두지 않습니다.
- 문단 카드는 8px 안팎의 촘촘한 간격을 사용하고 header·본문·footer의 내부 간격도 본문 읽기를 방해하지 않는 수준으로 제한합니다.
- 문단 본문 textarea가 카드의 주 콘텐츠이며 metadata와 동작이 이를 압도하지 않습니다.
- 잠긴 문단은 편집·삭제·부분 재작성할 수 없고 시각 상태와 비활성 상태가 일치합니다.
- 부분 재작성은 원문을 즉시 덮지 않고 변경안 비교 후 적용·폐기합니다.
- 설정 후보는 `이번 글만 / 설정 초안 / 정식 설정 승인`을 구분합니다.
- desktop에서는 본문과 `원고 도구` inspector가 독립적으로 접근 가능합니다. inspector는 `재작성 / 문장 점검 / 설정 후보`의 역할을 이름으로 밝히고 한 번에 한 도구만 보여 줍니다.
- mobile에서는 `원고 도구 보기`와 `초안으로 돌아가기`가 왕복을 제공합니다.

### 완성 다듬기와 완성본 만들기

- 완성 다듬기는 `초안에서 이어받은 원고 기준 / 보강 선택 deck`의 2열입니다. 왼쪽에는 글 만들기 때 정한 형식·시점·시제·목표 분량·전개 방식·문체를 읽기 전용으로 표시하며 이 값을 다시 선택하게 하지 않습니다.
- 오른쪽은 `문단 연결 / 인과 선명화 / 장면·감각 / 문장 리듬 / 중복 제거 / 결말 강화` 중 한 개 이상의 보강 목표, 다듬기 강도, 분량 방향과 이번 실행의 추가 요청만 받습니다.
- 완성본 만들기는 원래 설계와 선택한 보강 목표를 요약하고 로어북 저장 경계를 확인하는 면입니다. 항목마다 반복되는 `수정` 버튼을 두지 않고, 변경은 고정 footer의 `완성 다듬기` 복귀로 수행합니다.
- Finalizer는 최신 편집 초안 전체를 `editable_draft`로 받고 선택한 보강 범위 안에서 연결·중복·장면·리듬·결말을 다듬습니다. 새 설정을 만들거나 원래 형식·주제·관점을 다시 설계하지 않습니다.
- 완성본 저장 위치가 로어북이며 초안을 덮지 않는다는 경계를 명시합니다.
- 최종 CTA는 `초안 다듬어 로어북에 저장`처럼 입력에 가하는 작업과 저장 위치를 함께 말합니다.
- 원고가 로어북 생성 뒤 바뀌면 stale 경고와 재생성 동작을 제공합니다.
- 모바일에서 긴 초안·설정 다음 단계로 이동하면 이전 스크롤 위치를 유지하지 않고 새 단계 작업면의 시작을 보여 줍니다.

## 9. 05 로어북 `/lorebook`

### 페이지 역할

완성된 글을 읽고 필요한 경우 명시적으로 편집하며, 생성 당시 설정과 출처 초안을 확인하는 **완성본 책장**입니다.

### 현재 골격

```text
상단 page-tools: 열람 테마 | 현재 프로젝트
┌─ 책장 260px ─┬─ 완성본 읽기 minmax ─────────────────┐
│ 글 목록·개수   │ 제목·본문·편집 / 삭제·내보내기          │
│ 독립 스크롤     │ 출처 초안 링크 + 접힌 생성 설정 한 카드 │
└──────────────┴──────────────────────────────────────┘
```

- `.lorebook-layout`은 책장과 읽기 면의 2열입니다.
- 상단 `.page-tools` 왼쪽의 네 원형 버튼은 `노말 / 판타지아 / 메카니컬 / 어반 판타지` 열람 테마이며 현재 프로젝트 도구는 오른쪽에 둡니다. 선택은 브라우저 로컬 설정으로만 유지하며 프로젝트·본문·생성 입력·내보내기 데이터에 기록하지 않습니다.
- 노말은 기존 종이 문서를 보존합니다. 판타지아는 밝은 황백색 양피지와 굵은 적갈색 글자, 메카니컬은 거의 검은 단순 선형 CRT와 밝은 형광 녹색 글자·배경 한정 미세 글리치, 어반 판타지는 공포 질감이 없는 남색 기반 비 내린 도시 네온과 밝은 청백색 글자를 사용합니다.
- 비노말 테마에서는 `.workspace-main`의 문서 밖 여백을 해당 이미지보다 어두운 단색으로 연결합니다. `글 편집`은 테마가 덮어쓰지 않는 공통 진녹색·금색 버튼이며 모든 테마에서 같은 컴포넌트 표현을 유지합니다.
- 읽기·편집 양쪽에서 본문과 모든 동작의 대비를 유지하며 선택 상태는 금색 ring·번호·`aria-pressed`로 함께 표시합니다. 움직임 줄이기 환경에서는 CRT 글리치 애니메이션을 중단합니다.
- `.lorebook-sheet`는 입력 form이 아니라 종이 문서처럼 읽히는 것이 기본입니다.
- 데스크톱에서는 `.lorebook-reader`가 긴 제목·본문·하단 동작 전체의 단일 스크롤을 소유합니다. `.lorebook-sheet`가 본문 높이를 잘라 reader의 scrollHeight에서 제외하면 안 됩니다.
- `글 편집` 뒤에만 제목·Markdown 본문·상태 입력이 열립니다. 저장·취소 뒤 읽기 모드로 돌아갑니다.
- 읽기 모드는 `body_markdown`을 제목, 강조, 목록, 인용, 코드, 링크, 구분선으로 렌더링합니다. 원시 HTML은 실행하지 않고 문자로 표시하며 위험한 URL scheme은 링크로 만들지 않습니다.
- 삭제와 Markdown·HTML·JSON 내보내기는 읽기 상태의 문맥 동작입니다.
- `이 글을 만든 설정`은 출처 초안 링크와 같은 `.lorebook-source-link` 카드 안의 접힌 provenance이며, 독립 카드로 세로 공간을 점유하거나 본문보다 먼저 시선을 빼앗지 않습니다.
- 출처 초안 링크는 원본이 항상 별도로 보존된다는 설명과 함께 제공합니다.

### 모바일 목차→읽기

- `/lorebook`은 테마·프로젝트 command bar와 제목·문자 수·날짜를 훑는 목차만 보여 줍니다. select picker와 글 본문을 한 화면에 동시 표시하지 않습니다.
- 목차 카드를 누르면 `/lorebook?entry=<id>`의 독립 읽기 상태로 전환합니다. 이 상태에서는 command bar와 책장을 숨기고 `← 목차로`, 현재 글 번호, 제목·본문을 읽기 순서로 둡니다.
- `← 목차로`는 query를 제거하고 목차 상단으로 복귀합니다. 직접 URL 진입·새로고침·삭제 후에도 목차/읽기 상태가 꼬이지 않습니다.
- 선택한 테마는 목차 색·질감에서 읽기 시트로 이어지지만 query·본문·내보내기 데이터에 저장되지 않습니다.

## 9-A. 모델 연결 유틸리티 `/settings`

Writer·Utility·Vision·Embedding 역할별 OpenAI 호환 연결을 시험하고 저장하는 운영 화면입니다. 글·설정 자료를 다루는 여섯 번째 생명주기 페이지가 아니므로 `01–05` 번호와 모바일 하단 5칸을 유지합니다.

- 데스크톱에서는 좌측 메뉴 하단의 별도 `모델 연결`, 모바일에서는 우측 상단의 icon-only 톱니 링크로 접근합니다. 현재 위치는 `aria-current=page`로 표시합니다.
- `.model-profile-grid`는 데스크톱 2열, 820px 이하 1열입니다. 브라우저 자연 스크롤을 사용하고 마지막 Embedding 카드의 저장 버튼이 모바일 하단 메뉴에 가리지 않아야 합니다.
- 각 역할 카드는 Base URL, 모델 alias, API 키, timeout, context 예산과 `.env 기본값 / 앱 저장값` 출처를 보여 줍니다.
- API 키 입력은 password이며 비워 저장하면 기존 키를 유지합니다. 서버 응답·감사 로그는 키 원문을 반환하지 않고 `저장됨` 여부만 표시합니다.
- `연결 시험`은 저장하지 않습니다. `시험하고 저장`은 `/v1/models`와 alias를 확인한 경우에만 DB를 바꾸며, 실패하면 편집값과 재시도 동작을 유지합니다.
- Writer·Utility·Vision 카드의 `이 PC의 로컬 vLLM` 선택은 Qwen(`host.docker.internal:18091/v1`, `qwen36-heretic-mtp`)과 Gemma(`host.docker.internal:18093/v1`, `gemma4-26b-heretic-mtp`)를 각각 제공합니다. 역할별로 서로 다른 모델을 선택할 수 있고 `직접 입력`도 유지합니다.
- `이 PC 권장 분담 적용`은 Writer에 Gemma, Utility·Vision에 Qwen을 채우며 Embedding 값을 바꾸지 않습니다. 로컬 Qwen과 Gemma는 모두 `Thinking 끄기`를 기본으로 사용하고, thinking 비활성화는 응답 추론 모드만 바꾸며 vLLM native MTP를 끄지 않습니다.
- 인증 없는 신뢰 LAN 앱과 DB 평문 secret 저장 경계를 화면 하단에 경고하고 인터넷 직접 공개를 금지합니다.

## 13. 변경 시 적용 순서

1. 이 문서에서 변경할 페이지 역할과 유지할 계약을 표시한다.
2. 공통 class 변경이면 다섯 페이지의 소비 위치를 모두 검색한다.
3. desktop `1600×900`, mobile `390×844`, narrow mobile `360×844`에서 기준 골격을 비교한다.
4. 읽기·편집·빈 상태·오류·삭제·취소를 최소 한 번씩 통과한다.
5. `CHANGE_SAFETY_CHECKLIST.md`의 페이지별·공통 검사를 수행한다.
6. 의도적인 양식 변경은 이 문서와 Playwright 검증을 같은 커밋에서 갱신한다.

class 이름은 현재 구현을 찾기 위한 앵커입니다. 장기 계약은 class 문자열 자체가 아니라 **페이지 역할, 정보 우선순위, 상태 전이, 스크롤 소유권, 반응형 결과**입니다.
