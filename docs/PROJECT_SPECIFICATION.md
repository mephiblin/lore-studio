# Lore Studio 제품 및 구현 명세

## 1. 제품 정의

Lore Studio는 사용자가 직접 작성하거나 가져온 설정·이야기·참고자료를 **세계관 자료(ConceptPage)**로 축적하고, 선택한 소재와 프로젝트 **집필 지침**, 공유 **전개 방식**, **결과물 형태**, 분량·상세도·창작 자유도 설정을 조합해 로컬 LLM이 새로운 글을 작성하게 하는 로컬 우선 웹앱이다.

제품의 핵심은 “LLM에게 자료를 넣고 한 번 글을 받는 것”이 아니다. 생성된 초안을 편집하고 완성본을 로어북에 분리해 보관하며, 글 안의 설정 후보를 검토해 다시 세계관 자료로 편입함으로써 세계관과 글이 순환적으로 성장하는 데 있다.

```text
세계관 자료 축적
→ 글 만들기 선택
→ 사용할 설정·글의 흐름 확인
→ 초안 생성·편집
→ 완성본을 로어북에 저장
→ 설정 후보 추출·승인
→ 다음 생성에 재사용
```

## 2. 해결하려는 문제

일반적인 RAG 채팅과 범용 문서 앱은 다음 문제를 해결하지 못한다.

- 설정 자료와 작문 참고자료가 뒤섞인다.
- “무엇에 대해 쓸지”와 “어떤 방향으로 전개할지”가 한 프롬프트에 뭉친다.
- 원인→파급, 통념→재해석 같은 전개 패턴이 재사용 가능한 자산으로 남지 않는다.
- 생성된 글의 일부를 저장 가능하게 수정하거나 완성본으로 다시 다듬기 어렵다.
- LLM이 만든 새 사실이 다음 생성에서 자동으로 정식 설정처럼 증폭된다.
- 선택 자료의 역할과 프로젝트 경계가 불명확하면 관련 없는 사실이 섞인다.
- 긴 컨텍스트에 자료를 전부 넣어도 중요한 사실을 안정적으로 사용하지 못한다.

Lore Studio는 이 문제를 **데이터 층, 방향 층, 작문 층, 실행 층, 승인 층**으로 분리해 해결한다.

## 3. 핵심 도메인 객체

### 3.0 프로젝트(Project)

프로젝트는 하나의 세계관 namespace와 그 안의 자료·지침·원고를 묶는 최상위 경계다. 프로젝트 허브의 커버 이미지는 세계를 빠르게 구분하기 위한 선택 메타데이터이며 세계관 사실이나 생성 입력으로 사용하지 않는다. 원본 파일은 브라우저에서 16:9 JPEG로 축소·중앙 자르기한 후 프로젝트 설정에 저장한다.

### 3.1 세계관 자료(ConceptPage)

인물, 장소, 사건, 조직, 유물, 세계 규칙, 이야기 조각, 다른 IP 자료, 작문 참고 글 등을 노션형 자유 문서로 저장한다.

세계관 자료는 다음으로 구성된다.

- 제목
- 프로젝트가 정의한 자료 종류
- 태그
- 사용 역할
- 네임스페이스 또는 세계관
- 상태
- 선택적 속성
- 자유 본문
- 관련 페이지
- 유지할 사실
- 공개 유보 정보
- 금지된 변경·전개

구조화 필드는 도움을 주기 위한 것이며, 빈 칸을 채우도록 강제하지 않는다.

### 3.1.1 프로젝트 자료 종류(CategoryDefinition)

자료 종류는 전역 프리셋이 아니라 프로젝트 소유 분류다. 새 프로젝트에는 인물·장소·사건·유물·자유 페이지가 시작점으로 복사되지만, 이후에는 다른 프로젝트에 영향을 주지 않고 이름·설명을 수정하거나 새 종류를 만들 수 있다. 표시 이름을 바꿔도 내부 key와 기존 자료 연결은 유지한다. 사용 중인 종류는 바로 삭제할 수 없으며 자료를 다른 종류로 옮긴 뒤 명시적으로 삭제한다.

### 3.2 프로젝트 집필 지침(DirectionCard)

현재 프로젝트의 글에서 반복해 지킬 강조점·금지 사항·해석 경계를 지정하는 재사용 가능한 사용자 텍스트 하네스다. UI에서는 `집필 지침`으로 표시한다.

예:

- 제도의 초기 효능을 거짓으로 만들지 않는다.
- 기사단을 영웅으로만 미화하지 않는다.
- 백야항 시민의 생활 비용을 반드시 보여 준다.
- 확정되지 않은 범인의 정체를 단정하지 않는다.

카드는 자유 텍스트로 작성하고, 보조 LLM이 선택적으로 `must_include`, `avoid`, `sequence`, `ending_preference`를 제안한다.

### 3.3 전개 방식(WritingRecipe)

특정 소재의 목차가 아니라, 정보를 어떤 순서와 논리로 공개해 글을 만들어 갈지 정의한 작문 패턴이다. 기본 프리셋은 `project_id=NULL`이며 모든 프로젝트가 함께 사용하고, 사용자는 프로젝트 안에서 전용 방식을 생성·수정·안전 삭제할 수 있다. 글 만들기는 공용 방식과 현재 프로젝트 소유 방식만 허용한다.

기본 레시피:

- 큰 맥락에서 핵심으로
- 현재 흔적에서 과거로
- 목표에서 결과로
- 증거에서 판단으로
- 원인에서 파급으로
- 통념에서 재해석으로

“헤일로 디바이스식”은 유물의 기원·효과·단계적 변이를 복제하는 템플릿이 아니다. 넓은 맥락에서 대상으로 좁히고, 확정 사실과 예외·사례·해석을 교차시키며, 현상은 구체적으로 설명하되 근본 원인은 닫지 않는 **점층적 설정 풀이 방식**으로 일반화한다.

전개 방식은 결과물 형태와 독립적이다. 예를 들어 `원인에서 파급으로`는 세계관 설명 글, 영상 내레이션, 소설 장면 가운데 어느 결과물에도 적용할 수 있다.

### 3.4 글 만들기 기록(PlaybookSession)

세계관 자료, 프로젝트 집필 지침, 선택한 공용 또는 프로젝트 전개 방식, 결과물 형태, 생성 설정을 조합한 재현 가능한 실행 기록이다. 사용자 화면 이름은 `글 만들기`다.

글 만들기의 주요 입력:

- 주제
- 배경
- 주요 요소
- 갈등·변수
- 프로젝트 집필 지침 또는 이번 초안의 추가 지시
- 공유 전개 방식
- 결과물 형태
- 시점·시제
- 분량
- 상세도
- 자료 반영 범위
- 창작 자유도
- 미스터리 보존 정도
- 무작위 시드

### 3.5 초안과 로어북 문서

생성 결과는 채팅 메시지가 아니라 편집 가능한 초안이다. 문단 단위로 근거, 작문 역할, 확실성, 생성 실행을 연결한다. 제목·상태·전체 문단은 한 리비전으로 원자 저장한다. 완성 단계는 최신 초안과 사용자가 다시 확정한 설정을 Writer에 전달하며, 결과는 초안과 별도인 `document_kind=lorebook` 문서로 저장한다.

## 4. 자료의 사용 역할

모든 세계관 자료는 내용뿐 아니라 **어떻게 사용해도 되는가**를 가진다.

| 역할 | 의미 |
|---|---|
| `PROJECT_CANON` | 사용자 세계관의 승인된 사실 |
| `DRAFT_SETTING` | 변할 수 있는 초안 설정 |
| `CANON_EVIDENCE` | 특정 IP나 자료의 정식 설정 근거 |
| `SECONDARY_INTERPRETATION` | 위키·팬 해석·2차 정리 |
| `INSPIRATION` | 발상만 참고하고 사실은 가져오지 않음 |
| `DISCOURSE_REFERENCE` | 내용이 아니라 구성·문체·전개 방식 분석용 |
| `CANDIDATE` | LLM이 제안했으나 승인되지 않음 |
| `REJECTED` | 폐기된 설정, 생성에서 제외 |

다른 IP의 내용을 가져올 때 `namespace`와 `usage_role`을 함께 지정한다. 크로스오버를 명시하지 않은 경우 서로 다른 네임스페이스의 사실을 자동 혼합하지 않는다.

## 5. 핵심 제품 철학

### 5.1 사용자가 세계관의 권위자다

LLM은 요약·태그·관계·설정 후보를 제안할 수 있지만, 프로젝트 정식 설정의 최종 권한은 사용자에게 있다.

### 5.2 자유 문서가 먼저이고 구조화는 보조다

사용자가 데이터베이스를 관리하는 노동 때문에 창작을 포기해서는 안 된다. 자유롭게 쓰고, LLM이 속성과 관계를 제안하며, 필요한 부분만 승인한다.

### 5.3 생성보다 조합과 수정이 중요하다

좋은 결과를 한 번 뽑는 것보다, 소재·방향·작문 방식을 이해 가능한 단위로 선택하고 결과의 일부만 수정하며 재사용할 수 있어야 한다.

### 5.4 작문 방식은 재사용 가능한 자산이다

좋아하는 로어 글을 통째로 프롬프트에 넣는 대신, 문단 역할·스케일 변화·확실성 곡선·문장 리듬을 분석해 전개 방식과 Voice Profile 후보로 저장한다.

### 5.5 선택은 사용자가 만든 경계 안에서 작동한다

자료는 현재 프로젝트 안에서 주제·배경·주요 요소·갈등 역할별로 선택한다. 앞 단계에 배정한 자료는 뒤 역할 후보에서 제외하며, 다른 프로젝트나 네임스페이스의 사실을 자동 혼합하지 않는다.

### 5.6 컨텍스트는 컴파일된다

선택한 페이지를 전부 이어 붙이지 않는다. 다음 묶음으로 정리한다.

1. 반드시 지켜야 할 사실
2. 주요 페이지 요약
3. 직접 관련 원문
4. 관계와 시대 정보
5. 충돌하거나 불확실한 내용
6. 창작 가능한 공백
7. 폐기·금지 설정
8. 프로젝트 집필 지침
9. 공유 전개 방식
10. 사용자 추가 지시

### 5.7 생성은 추적 가능해야 한다

모델, 런타임, 프롬프트 구성요소 버전, 선택한 세계관 자료, 집필 지침, 전개 방식, 결과물 형태, 시드, 샘플링 파라미터를 저장한다.

## 6. 주요 사용자 흐름

### 6.1 세계관 자료 축적

```text
프로젝트 선택
→ 세계관 자료 생성
→ 프로젝트 자료 종류·태그·사용 역할 지정
→ 자유 본문 작성
→ 자동 요약·태그·관계 제안 검토
```

### 6.2 초안 생성

```text
글 만들기 열기
→ 주제·배경·주요 요소·갈등 자료를 순서대로 선택
→ 프로젝트 집필 지침 선택 또는 추가 지시
→ 공유 전개 방식 선택
→ 결과물 형태·시점·시제 선택
→ 분량·상세도·자료 범위·창작 자유도 설정
→ 사용할 설정 확인
→ 글의 흐름 생성·수정·저장
→ 초안 작성
→ 해당 초안을 원고 작업에서 열기
```

### 6.3 초안 편집과 완성

```text
제목·상태·문단 수정 또는 문단 추가·삭제
→ 초안 전체 저장 또는 다음 단계 이동 시 자동 저장
→ 필요하면 문단 선택
→ 더 짧게 / 더 자세히 / 사례 추가
→ 설명형↔장면형 변환
→ 사실은 유지하고 문체만 변경
→ 문단 잠금
→ 앞뒤 연결만 재작성
→ 완성 설정을 다시 수정
→ 최신 초안 전체를 한 편의 글로 다듬기
→ 완성본을 로어북에 별도 저장
```

### 6.4 세계관 순환

```text
초안에서 설정 후보 추출
→ 이번 글만 / 설정 초안 / 정식 설정 중 사용자가 결정
→ 정식 설정 승인은 CANDIDATE → DRAFT_SETTING → PROJECT_CANON 이력 기록
→ 다음 글 만들기에서 재사용
```

## 7. 생성 설정의 의미

### 출력 분량

- 짧게
- 보통
- 길게
- 매우 길게
- 직접 지정

### 상세도

문장을 늘리는 수치가 아니라, 원인·결과·예외·사회적 영향·상반된 해석·장기 파급을 얼마나 포함할지 결정한다.

### 자료 반영 범위

- 핵심만: 요약과 잠긴 사실
- 균형: 직접 관련 원문과 1단계 관계
- 넓게: 선택 페이지 전체와 관계 페이지
- 최대: 허용 토큰 안에서 관련 자료를 최대한 검색

### 창작 자유도

- 엄격: 기록된 사실만
- 보수적: 세부 묘사와 작은 인과 연결 허용
- 균형: 핵심 설정을 지키며 공백을 적극적으로 메움
- 자유: 새로운 인물·사건·세부 설정도 생성

## 8. 비기능 요구사항

- 외부 클라우드 없이 로컬에서 동작 가능
- OpenAI 호환 모델 서버 교체 가능
- NAS 원본 자료와 DGX 로컬 인덱스 분리 가능
- 단일 사용자부터 시작하되 프로젝트·사용자 키를 확장 가능
- 문서와 생성 실행 버전 관리
- 데이터 내보내기 가능
- 모델이 중단되어도 사용자 문서 손상 없음
- 검색이나 모델 실패 시 원인을 UI에 명확히 표시

## 9. MVP 완료 기준

사용자가 다음 작업을 UI에서 끝낼 수 있어야 한다.

1. 프로젝트를 만든다.
2. 세계관 자료를 여러 개 작성하고 관계를 연결한다.
3. 필요하면 프로젝트 집필 지침을 만든다.
4. 세계관 자료와 집필 지침을 글 만들기에서 선택한다.
5. 전개 방식, 결과물 형태, 시점·시제와 분량·상세도·창작 자유도를 고른다.
6. 사용할 설정을 확인한다.
7. 글의 흐름을 생성·수정·저장한다.
8. 초안을 생성하고 제목·문단 추가/수정/삭제를 저장한다.
