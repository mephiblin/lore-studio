# Lore Studio 제품 및 구현 명세

## 1. 제품 정의

Lore Studio는 사용자가 직접 작성하거나 가져온 설정·이야기·참고자료를 **컨셉 페이지**로 축적하고, 선택한 소재와 **방향성 카드**, **집필 레시피**, 분량·상세도·창작 자유도 설정을 조합해 로컬 LLM이 계속 새로운 로어를 작성하게 하는 로컬 우선 웹앱이다.

제품의 핵심은 “LLM에게 자료를 넣고 한 번 글을 받는 것”이 아니다. 생성된 글을 편집하고, 그 안의 새로운 설정을 검토해 다시 컨셉 페이지로 편입함으로써 세계관과 글이 순환적으로 성장하는 데 있다.

```text
컨셉 페이지 축적
→ 플레이북 조합
→ 구성안·로어 생성
→ 사용자 편집·승인
→ 새 컨셉 후보 추출
→ 다음 생성에 재사용
```

## 2. 해결하려는 문제

일반적인 RAG 채팅과 범용 문서 앱은 다음 문제를 해결하지 못한다.

- 설정 자료와 작문 참고자료가 뒤섞인다.
- “무엇에 대해 쓸지”와 “어떤 방향으로 전개할지”가 한 프롬프트에 뭉친다.
- 소설형, 극화형 로어, 점층적 설정 풀이형 등 작문 방식이 재사용 가능한 자산으로 남지 않는다.
- 생성된 글의 일부만 수정하거나 다른 형식으로 재활용하기 어렵다.
- LLM이 만든 새 사실이 다음 생성에서 자동으로 정사처럼 증폭된다.
- 무작위 조합이 전 데이터베이스에서 무질서하게 일어나 실용성이 낮다.
- 긴 컨텍스트에 자료를 전부 넣어도 중요한 사실을 안정적으로 사용하지 못한다.

Lore Studio는 이 문제를 **데이터 층, 방향 층, 작문 층, 실행 층, 승인 층**으로 분리해 해결한다.

## 3. 사용자에게 보이는 다섯 객체

### 3.1 컨셉 페이지

인물, 장소, 사건, 조직, 유물, 세계 규칙, 이야기 조각, 다른 IP 자료, 작문 참고 글 등을 노션형 자유 문서로 저장한다.

컨셉 페이지는 다음으로 구성된다.

- 제목
- 주 카테고리
- 태그
- 사용 역할
- 네임스페이스 또는 세계관
- 상태
- 선택적 속성
- 자유 본문
- 관련 페이지
- 잠긴 사실
- 열린 질문

구조화 필드는 도움을 주기 위한 것이며, 빈 칸을 채우도록 강제하지 않는다.

### 3.2 방향성 카드

이번 글에서 어떤 변화·갈등·해석·결말을 향할지 지정하는 재사용 가능한 사용자 텍스트 하네스다.

예:

- 해결책이 사회적 의존으로 변한다.
- 조사 기관이 현상을 잘못 분류한 상태로 시작한다.
- 현재의 폐허에서 출발해 과거의 정상 상태로 거슬러 올라간다.
- 진실을 완전히 공개하지 않고 상반되는 두 해석을 남긴다.

카드는 자유 텍스트로 작성하고, 보조 LLM이 선택적으로 `must_include`, `avoid`, `sequence`, `ending_preference`를 제안한다.

### 3.3 집필 레시피

특정 소재의 목차가 아니라, 정보를 어떤 순서와 논리로 공개해 글을 만들어 갈지 정의한 작문 전략이다.

기본 레시피:

- 소설 장면형
- 극화형 로어
- 점층적 설정 풀이형
- 인-유니버스 문서형

“헤일로 디바이스식”은 유물의 기원·효과·단계적 변이를 복제하는 템플릿이 아니다. 넓은 맥락에서 대상으로 좁히고, 확정 사실과 예외·사례·해석을 교차시키며, 현상은 구체적으로 설명하되 근본 원인은 닫지 않는 **점층적 설정 풀이 방식**으로 일반화한다.

### 3.4 플레이북

컨셉 페이지, 방향성 카드, 집필 레시피, 출력 프로필, 생성 설정을 조합하는 실행 화면이다.

플레이북의 주요 입력:

- 주요 대상
- 배경
- 등장 요소
- 갈등·변수
- 무작위 풀
- 방향성 카드 또는 임시 사용자 지시
- 집필 레시피
- 출력 형식
- 분량
- 상세도
- 자료 반영 범위
- 창작 자유도
- 미스터리 보존 정도
- 무작위 시드

### 3.5 로어 문서

생성 결과는 채팅 메시지가 아니라 편집 가능한 문서다. 문단 단위로 근거, 작문 역할, 확실성, 생성 실행을 연결할 수 있어야 한다.

## 4. 자료의 사용 역할

모든 컨셉 페이지는 내용뿐 아니라 **어떻게 사용해도 되는가**를 가진다.

| 역할 | 의미 |
|---|---|
| `PROJECT_CANON` | 사용자 세계관의 승인된 사실 |
| `DRAFT_SETTING` | 변할 수 있는 초안 설정 |
| `SOURCE_EVIDENCE` | 특정 IP나 자료의 사실 근거 |
| `SECONDARY_INTERPRETATION` | 위키·팬 해석·2차 정리 |
| `INSPIRATION_ONLY` | 발상만 참고하고 사실은 가져오지 않음 |
| `DISCOURSE_REFERENCE` | 내용이 아니라 구성·문체·전개 방식 분석용 |
| `CANDIDATE` | LLM이 제안했으나 승인되지 않음 |
| `REJECTED` | 폐기된 설정, 생성에서 제외 |

다른 IP의 내용을 가져올 때 `namespace`와 `usage_role`을 함께 지정한다. 크로스오버를 명시하지 않은 경우 서로 다른 네임스페이스의 사실을 자동 혼합하지 않는다.

## 5. 핵심 제품 철학

### 5.1 사용자가 세계관의 권위자다

LLM은 요약·태그·관계·새 설정을 제안할 수 있지만, 프로젝트 정사의 최종 권한은 사용자에게 있다.

### 5.2 자유 문서가 먼저이고 구조화는 보조다

사용자가 데이터베이스를 관리하는 노동 때문에 창작을 포기해서는 안 된다. 자유롭게 쓰고, LLM이 속성과 관계를 제안하며, 필요한 부분만 승인한다.

### 5.3 생성보다 조합과 수정이 중요하다

좋은 결과를 한 번 뽑는 것보다, 소재·방향·작문 방식을 이해 가능한 단위로 선택하고 결과의 일부만 수정하며 재사용할 수 있어야 한다.

### 5.4 작문 방식은 재사용 가능한 자산이다

좋아하는 로어 글을 통째로 프롬프트에 넣는 대신, 문단 역할·스케일 변화·확실성 곡선·문장 리듬을 분석해 집필 레시피와 Voice Profile로 저장한다.

### 5.5 무작위는 사용자가 만든 경계 안에서 작동한다

전체 DB에서 무작위로 뽑지 않는다. 저장 필터와 카테고리·태그·최근 사용 여부로 정의한 풀에서 역할별로 추첨한다.

### 5.6 컨텍스트는 컴파일된다

선택한 페이지를 전부 이어 붙이지 않는다. 다음 묶음으로 정리한다.

1. 반드시 지켜야 할 사실
2. 주요 페이지 요약
3. 직접 관련 원문
4. 관계와 시대 정보
5. 충돌하거나 불확실한 내용
6. 창작 가능한 공백
7. 폐기·금지 설정
8. 방향성 카드
9. 집필 레시피
10. 사용자 추가 지시

### 5.7 생성은 추적 가능해야 한다

모델, 런타임, 프롬프트 구성요소 버전, 선택한 페이지, 방향 카드, 레시피, 시드, 샘플링 파라미터를 저장한다.

## 6. 주요 사용자 흐름

### 6.1 컨셉 축적

```text
프로젝트 선택
→ 페이지 생성 또는 자료 가져오기
→ 카테고리·태그·사용 역할 지정
→ 자유 본문 작성
→ 자동 요약·태그·관계 제안 검토
```

### 6.2 로어 생성

```text
플레이북 열기
→ 주요 대상과 관련 페이지 선택
→ 필요하면 저장 필터에서 무작위 추첨
→ 방향성 카드 선택 또는 직접 지시
→ 집필 레시피·출력 형식 선택
→ 분량·상세도·자료 범위·창작 자유도 설정
→ 컨텍스트 미리보기
→ 구성안 생성
→ 구성안 수정·승인
→ 전체 원고 생성
```

### 6.3 결과 수정

```text
문단 선택
→ 더 짧게 / 더 자세히 / 사례 추가
→ 설명형↔장면형 변환
→ 사실은 유지하고 문체만 변경
→ 다른 방향성 카드 적용
→ 문단 잠금
→ 앞뒤 연결만 재작성
```

### 6.4 세계관 순환

```text
완성 원고 저장
→ 새 설정 후보 추출
→ 새 페이지 / 기존 페이지 추가 / 이번 글 전용 / 폐기
→ DRAFT_SETTING 또는 PROJECT_CANON으로 승인
→ 다음 플레이북에서 재사용
```

## 7. 생성 설정의 의미

### 출력 분량

- 짧게
- 보통
- 길게
- 매우 길게
- 직접 지정

### 상세도

문장을 늘리는 수치가 아니라, 원인·결과·예외·사회적 영향·상반된 해석·장기 파급을 얼마나 포함할지 결정한다.

### 자료 반영 범위

- 핵심만: 요약과 잠긴 사실
- 균형: 직접 관련 원문과 1단계 관계
- 넓게: 선택 페이지 전체와 관계 페이지
- 최대: 허용 토큰 안에서 관련 자료를 최대한 검색

### 창작 자유도

- 엄격: 기록된 사실만
- 보수적: 세부 묘사와 작은 인과 연결 허용
- 균형: 핵심 설정을 지키며 공백을 적극적으로 메움
- 자유: 새로운 인물·사건·세부 설정도 생성

## 8. 비기능 요구사항

- 외부 클라우드 없이 로컬에서 동작 가능
- OpenAI 호환 모델 서버 교체 가능
- NAS 원본 자료와 DGX 로컬 인덱스 분리 가능
- 단일 사용자부터 시작하되 프로젝트·사용자 키를 확장 가능
- 문서와 생성 실행 버전 관리
- 데이터 내보내기 가능
- 모델이 중단되어도 사용자 문서 손상 없음
- 검색이나 모델 실패 시 원인을 UI에 명확히 표시

## 9. MVP 완료 기준

사용자가 다음 작업을 UI에서 끝낼 수 있어야 한다.

1. 프로젝트를 만든다.
2. 컨셉 페이지를 여러 개 작성한다.
3. 방향성 카드를 만든다.
4. 페이지와 카드를 플레이북에서 선택한다.
5. 집필 레시피와 분량·상세도·창작 자유도를 고른다.
6. 컨텍스트 미리보기를 확인한다.
7. 구성안을 생성한다.
8. 로어 글을 생성하고 문서로 저장한다.
9. 생성 이력과 사용된 입력을 확인한다.
10. 새 설정을 자동 정사 편입하지 않는다.
